# REINIT-04 plan (#28): measure the registered Godunov2 operator on v17 before designing anything new

Date: 2026-10-15. Issue: [#28](https://github.com/ramhachi/CFD_opt_sdf/issues/28). Evidence class (target): solver-free operator-effect capability on
two canonical v17 states. No CFD. Order authority: `docs/phase_plan.md` (#29 closed → **#28** → #25 → #30).

## Need

#30 (OPT-01) takes several topology-fixed steps. Without reinitialization the distance property drifts (Eikonal median 2.5e-7 on the v17
baseline, 0.0121 after one 1.25 mm LOWDIM step; GEOM-02 limit 0.10) and the GEOM-02 gradient-floor failures grow from 106 to 154 nodes, nearly all
kinks ([#29 record](issues/29_geom02_result_2026_10_14.md)). The only registered operator, `sdf_native_reinitialization_godunov2_v2`, failed in
Round 3 (2026-10-01) on the analytic thin box and on canonical **v16** (smoothed-volume drift 32%, zero-level displacement 0.50 edges,
idempotence 0.65h), largely from one-cell plates that v17 (h/2 genesis) no longer has. It was never run on v17. Ponytail: measure the existing
operator on v17 first; design a new one only if this fails.

## Question

Does the unchanged registered operator, applied once to the v17 baseline and to the LOWDIM-03 parent, stay within the unchanged registered
`canonical` tolerances and keep the states GEOM-02- and P22-v2-admissible? Secondary (descriptive): does it remove the kinks that the
un-reinitialized step added (parent 149) while, as expected, leaving geometric ones?

## Fixed inputs (nothing new is designed)

- Operator: `reinitialize_sdf(state, profile="canonical", fail_closed=False)` from `src/cfd_sdf/design/sdf_reinitialization.py`, unchanged (the
  file is hashed by the frozen LOWDIM-03 closure: do not edit). Contract payload hash recorded.
- Its own gates with the unchanged `TOLERANCES` (`canonical` profile: Eikonal p50 ≤ 0.10, p95 ≤ 0.50, zero-level displacement ≤ 0.25 edges,
  sharp and smoothed volume drift ≤ 5%, idempotence ≤ 0.10h). No threshold is added to or relaxed in this contract.
- GEOM-02 bundle (`geometry_gates_v2`, registered profile `af3d74c8…`, resolved policy `b5bcc8c7…`) on each output, as a transition from its
  input with `allowed_events=()`.
- P22-v2 hard count `N_phi ≤ 8272` on each output (the operator keeps node signs, but cell-centre corner means can change sign).
- Inputs: `v17_baseline.npz` (`7a972b33…`) and `lowdim03_parent.npz` (`0ce3256b…`), hash-checked.

## Verdict (preregistered)

- `REINIT04_BOUNDED_ON_V17` iff, for both states: every operator gate passes, every GEOM-02 gate that passed on the input still passes
  on the output, and `N_phi ≤ 8272`.
- `REINIT04_NOT_BOUNDED` otherwise (each failing gate named). `REINIT04_INCOMPLETE` on any hash mismatch, exception or non-finite output.
- `near_zero_gradient_band` is **not** in the verdict (it already fails on both inputs, and kinks are expected to survive); its counts and the
  kink / tie_plateau / other classification (the `scripts/geom02_gradient_floor_diagnostic.py` rule, reused) are reported before and after.
- The analytic fixtures are not rerun (Round 3 results stand: thin box FAIL). The verdict therefore says nothing about general shapes.

## Use of the outcome

- BOUNDED: #30 may apply this operator after an accepted update under these gates (registered as a post-acceptance step; it stays outside the
  `phi -> response` FD map). Not a general qualification; `topology_birth`/`shape_update_allowed` unchanged.
- NOT_BOUNDED: #30 runs without reinitialization and relies on the GEOM-02 distance gate; a new operator is a separate plan.
- Either way the gradient-floor rule decision (record of #29) stays open and is taken separately, informed by the before/after kink counts.
