# CFD_opt_sdf 開発全体計画書

**32GBのMac・Windowsで使う、SDFベースの空力形状・トポロジー最適化**

作成日：2026-09-06

版：1.1

位置付け：先行レビューを反映した採用済み設計・受入基準。2026-09-07に実装着手し、2026-09-09にプロジェクトの本採用アーキテクチャとした。最新の進捗・実行順序は [phase_plan.md](phase_plan.md) を正とする。

基準リポジトリ：ramhachi/CFD_opt_sdf、commit fdc105343c275b9fe80c2c9d8ea6b9eca3cb7287。

## 1. 目的と完成像

任意のSTL形状について、空力性能、取り付け部との接続、禁止領域、最小厚さ・隙間を満たす形状を、32GBのローカル機で反復的に設計できるようにする。

フロントウイングを最初の複雑な適用例とするが、問題定義や座標系を翼専用にはしない。高速化の指標は、単体ソルバの速度ではなく、**制約を満たし、独立したCFDでも改善が確認できる形状を得るまでの総時間**とする。

完成時の利用手順は次の通り。

1. STL、設計可能領域、固定物、禁止領域、取り付け部、流れの条件を指定する。
2. 幾何と解像度の検査で、計算できない設定や表現できない細部を検出する。
3. 必要に応じてトポロジーを探索し、SDFで形状を精緻化する。
4. 各候補の流れ・目的・制約を再評価して、改善した候補を採用する。
5. 別の格子とbody-fitted CFDで最終候補を評価する。
6. 形状、性能、制約、計算条件、再開データを出力する。

## 2. 採用する方針

| 項目 | 決定 |
|---|---|
| 開発場所 | 既存リポジトリ内で進める。初期に新リポジトリを作らない |
| 問題定義 | ProblemSpec v2、幾何役割、単位、応答ID、履歴追跡を再利用 |
| トポロジー探索 | 既存の固定格子density/Brinkman経路を残し、段階的に完成させる |
| 形状精緻化 | SDFを主表現とし、境界位置を連続的に変更する |
| 高速CFD | LBMを実験バックエンドとして追加し、適用範囲を検証してから実用経路へ昇格 |
| 参照CFD | OpenFOAMを維持。対象条件の検証を進める |
| 随伴 | 初期は収束した定常離散問題のimplicit adjoint |
| GPU対応 | WindowsはCUDA、Apple Silicon MacはMetal。物理と判定条件を共通化 |
| 最適化 | SDF経路は拡張ラグランジュ＋平滑化した形状更新を初期方式とする |
| 格子 | 初期は一様格子。必要性が確認された場合に静的2段階細分化 |
| 初期値 | 直前の収束解を再利用。MLは初期の必須項目にしない |

ソルバ置換は、同じ問題・精度・制約で優位性が確認された範囲から行う。LBMが対象空力に適合しない場合は、既存CFD経路を継続し、検証・最適化・OS対応の成果をそのまま活用する。

## 3. 対象範囲と物理モデル

### 3.1 初期に対応する範囲

- 剛体、単一材料、低Machの外部流れ。
- STLで指定する固定物、初期形状、設計領域、禁止領域、取り付け部。
- 力を基本とする目的・制約。係数化に使う面積・速度・密度を明示する。
- 単一条件から開始し、後に少数の運転条件を決定的に集約する。
- 定常層流で数値手法を検証し、対象Reの空力は別途物理を認定する。

翼の最初の適用では、例えばダウンフォース最大化とdrag上限を使う。効率下限制約を使う場合はdragの符号・下限を確認した上で等価な式へ変換する。一般的な応答の仕組みは維持する。

### 3.2 流れの計算と勾配の対応

| 用途 | 物理・勾配の扱い |
|---|---|
| 手法の成立確認 | 定常層流＋離散随伴 |
| 対象Reの参照評価 | 検証したOpenFOAM RANSを基準。乱流・遷移・壁面条件の適用範囲を記録 |
| 高速モデルによる対象空力の探索 | 主問題の応答と局所的な形状変更の効果が参照計算と整合した範囲だけ使用 |
| 非定常LBMの平均力 | 前進計算の比較には使えるが、平均場に定常随伴を適用しない |

定常RANSの勾配を扱う場合は、乱流変数と壁面処理を含む線形化を原則とする。凍結乱流などの近似を用いる場合は、その近似と誤差を明示し、完全な勾配と区別する。

対象条件で非定常統計量の勾配が不可欠と判明した場合は、初期の定常最適化から切り離す。高Reの流れが安定して計算できることだけで、時間平均の勾配まで認定しない。

### 3.3 初期に含めない範囲

完全非定常最適化、流体構造連成、圧縮性流れ、回転タイヤを含む車両全体、動的AMR、真のtopological derivative、MLによるCFD置換は後続段階とする。

## 5. Mac・Windows対応

| 項目 | Windows機 | Mac |
|---|---|---|
| ユーザー指定メモリ | RAM 32GB | RAM 32GB |
| GPU前提 | RTX 4070 Ti、標準VRAM 12GB | チップ型番は着手時に確認 |
| 基準実行環境 | WSL2/Linux＋CUDA | Apple Siliconを前提にmacOS＋Metal |
| 初期GPU候補 | XLB/Warp | MLX custom Metal |
| 小規模参照 | CPU FP64 | CPU FP64 |
| OpenFOAM | 現行版を固定したLinux環境 | 同じソルバ系統の検証可能なLinux環境を用意 |

Windowsでは32GB RAMと12GB VRAMを別に管理する。MacでもOS・可視化・他アプリとメモリを共有する。MacがIntelの場合は、Metal案の適用可否とGPU構成を先に見直す。

両OSで、同じ問題ファイル、同じ応答の定義、同じ結果形式、同じ受入条件を使う。初期から小規模な共通CFDケースを両機で実行し、最大問題規模は機種別に設定する。

環境差は起動・パス・依存関係の層に閉じ込める。Windows専用PowerShell手順に加え、Python CLIを共通入口として整える。MacのOpenFOAMについては、コンテナのCPUアーキテクチャ、拡張ライブラリのビルド、速度を確認し、無検証のエミュレーションを性能基準にしない。

二種類のカーネル実装を始める前に、CUDA/Metalへ共通記述できる既存基盤を最大数日の小試験で比較してよい。採用判断は一度に限定し、三つ目の開発ラインは維持しない。XLBのNeonによる細分化は後段の別環境として扱う。

## 6. 数値計算と最適化の仕様

### 6.1 SDFと形状の扱い

SDFは固体内部を負、流体側を正とする。設計用密度は材料量、流体の密度は物性値として名前と単位を分ける。

界面リンクの位置はSDF値から補間する。流体・固体分類が変わったときは、境界リンク、新しい流体セルの状態、質量・境界整合を更新する。

形状更新には法線方向の形状勾配を使う。格子値に対する微分から直接速度を作らず、内積、界面上の感度、速度の拡張方法を定義する。再初期化は必要な場合に実施し、ゼロ等値面の移動と体積変化を監視する。

密度からSDFへ渡す際は、体積、表面位置、連結成分、取り付け部、厚さ・隙間の変化を測る。誤差が大きければ格子・抽出条件を見直し、その候補を精緻化済みとして扱わない。

### 6.2 随伴

定常残差をR、流れの状態をU、設計変数をd、目的をJとすると、

\[
R(U,d)=0,\qquad
R_U^T a=J_U^T,\qquad
\frac{dJ}{dd}=J_d-a^TR_d
\]

を基本とする。dが密度かSDFかを成果物に明記する。目的そのものの直接設計微分を含める。

随伴の線形解法は、一様格子の小規模例で固定点反復とメモリを限定したKrylov法を比較して一つを選ぶ。主状態、右辺、反復ベクトル、作業配列を含む総量を測定する。全時間履歴を保存する自動微分は小規模な検証用に限る。

### 6.3 制約付き更新

SDF経路では、初期方式として不等式に対応したPHR型拡張ラグランジュを用いる。

\[
\mathcal L_\mu
=f+\sum_i\frac{[\lambda_i+\mu g_i]_+^2-\lambda_i^2}{2\mu},
\qquad g_i\le0.
\]

内側の更新では乗数とペナルティを固定する。一定の内側収束または外側更新点で、乗数を

\[
\lambda_i^+=[\lambda_i+\mu g_i]_+
\]

と更新する。制約を無次元化し、ペナルティの無制限な増加を避ける。

単一の流れ状態に対しては、合成目的の随伴を一つに集約できる。複数流れ条件は逐次求解し、各条件の寄与を合算する。

density経路は既存の制約更新インターフェースを活用し、非線形再評価を備えたGCMMA等の既存方式を利用する。初期からSDF経路とアルゴリズムを無理に統一しない。

### 6.4 反復手順

1. 現在の形状の流れを求解し、収束と力を確認する。
2. 必要な随伴を解き、勾配を得る。
3. 勾配を平滑化し、移動上限付きで候補を作る。
4. 固定物、禁止領域、取り付け部、最小寸法を検査する。
5. 必要な幾何処理・再初期化を終えた候補の流れを再計算する。
6. 同じ乗数・ペナルティでの目的と制約を比較し、十分な改善があれば採用する。
7. 棄却時は最後の採用状態へ戻して刻みを縮小する。再試行上限で改善不能なら理由を記録して停止する。
8. 採用状態と乗数・制御値を保存する。乗数更新後は新しい合成目的で勾配を計算する。

幾何のhard constraintは満たした候補だけ採用する。空力の不等式は初期に未充足でも探索可能とするが、最終合格は全て充足した候補に限る。制約の可行性回復を優先する条件を明示し、失敗候補を最良の可行解として出力しない。

## 7. 検証と完成条件

### 7.1 共通ルール

「ファイルの整合」「ソルバが動く」「数値的に収束」「対象物理が妥当」「最適化結果が妥当」を別々に記録する。ある段階の成功で次の段階を代用しない。

| 検証対象 | 確認項目 |
|---|---|
| 幾何 | 単位、閉曲面、異常STL、役割mask、表面誤差、連結性、厚さ・隙間 |
| 流れ | 残差、質量収支、力の定常性、境界条件、圧力・摩擦の寄与 |
| 格子 | 少なくとも3段階で応答と重要な局所量の変化を確認 |
| 勾配 | kernel転置積、FDの刻み掃引、Taylor test、直接設計微分 |
| 形状更新 | 固定リンクでの微分と、格子横断・再初期化の有限更新を別々に試験 |
| 両OS | 同じ離散化で力・残差・方向微分が許容誤差内で一致 |
| 最適化 | 候補の実改善、制約充足、棄却・再開、初期形状依存 |
| 最終結果 | 最適化に使わない格子・運転条件で独立評価 |

誤差許容値は、最初の物理プロファイルで期待改善量と制約余裕から決め、最適化開始前に固定する。ゼロ付近の量には絶対誤差も使う。結果を見て閾値を緩める場合は再認定として記録する。

研究用の初期目安として、小規模FP64層流の有効な方向微分では1%以内の相対誤差を狙う。ただし一点の一致だけで合格とせず、刻みを変えた整合とTaylor残差の二次領域を確認する。FP32・格子横断には別の許容条件を設定する。

### 7.2 独立した空力評価

参照CFDも格子とモデルの不確かさを持つ。最終候補と初期形状を同じ参照条件で評価し、改善量の不確かさを含めて判定する。

初期の高精度監査は、初期形状、最初の採用候補、以後5採用ステップごと、最終候補を暫定の実行頻度とする。大きな形状・トポロジー変更、格子変更、制約限界への接近時は追加する。これは実装上の初期設定であり、収束理論に基づく頻度ではない。

監査で改善の反転や制約違反が出たら、最後の高精度で確認済みの形状へ戻り、モデル・解像度・許容移動量を見直す。符号一致や順位相関は診断に使うが、最終合格の単独条件にしない。

正式なmultifidelity trust-regionは、局所的な差の補正と予測改善/実改善による半径更新まで実装する段階で導入する。

## 8. 計算資源と性能目標

| 項目 | 初期の設計方針 |
|---|---|
| Windows GPU常駐量 | 8–9GB程度を暫定予算にし、実機の空きとピークで調整 |
| Mac solver working set | 12–16GB程度を暫定予算にし、memory pressureを確認 |
| 計算精度 | GPU FP32、小規模CPU FP64参照。低精度化は検証後 |
| 格子規模 | 最小寸法と流れの解像度から算出。5Mセルを先に固定しない |
| 複数条件 | 初期は逐次実行して状態の同時保持を避ける |
| 初期値 | 直前の収束解を再利用し、新しい流体セルを整合的に補完 |
| 出力 | 毎回は要約、採用時は再開用状態、指定間隔で可視化 |
| 測定範囲 | 幾何、主問題、随伴、候補再評価、転送、I/O、高精度監査 |

5Mセルで主問題＋随伴15分以内は挑戦目標として残すが、適切な物理解像度と同じ収束条件を満たした場合だけ評価する。総最適化時間には棄却候補と監査を含める。

高速バックエンドの昇格条件は、同じ精度・制約で参照経路より短時間に改善結果へ到達すること。測定ばらつき程度の速度差だけなら、保守対象を増やす置換は行わない。

## 9. 開発フェーズ

期間は担当者1名を中心に進める場合の作業枠であり、性能や完成時期の保証ではない。判定に失敗した場合は、対象範囲を狭めるか既存経路へ戻り、後続機能を積み増さない。

### P0：共通基盤と参照条件の固定 — 1週目

**作業**

- Mac型番・GPU、Windowsの実使用可能VRAM、実行環境を確認する。
- 対象の速度、Re、代表長さ、厚さ・隙間・地上高、物理モデルを一つ決める。
- 現行G2をdomain-bound条件で再認定し、必要な単位・格子・勾配の意味を接続する。
- 既存計算の時間内訳を測る。
- 両OSで問題読込、幾何検査、小規模参照ケースの起動を確認する。

**成果物**：環境表、問題プロファイル、基準ケース、計時結果、残課題一覧。

**完了条件**：同じ問題と応答を再現でき、何を高速化するか説明できる。

### P1：LBM前進計算の適合性判断 — 2〜4週目

**作業**

- XLBの既存部品を使い、一つの構成で小規模な流れを計算する。
- Taylor–Green、定常低Re円柱等で数値の基礎を確認する。
- 対象Reの単純翼・地面の固定形状を早期に試し、圧力・力・摩擦・必要解像度を参照と比較する。
- 必要なら非定常平均を用いるが、定常随伴の認定と混同しない。
- 新規MRT、LKS、AMRは作らない。

**成果物**：速度・メモリ・応答比較、採用する衝突/境界構成、適用可能な物理範囲。

**完了条件**：LBMを継続する用途が明確で、メモリと物理の致命的な不適合がない。対象空力に不適合なら、低Re研究用に限定して既存CFDで実用経路を進める。

### P2：SDF境界・定常随伴・両GPU — 2か月目

**作業**

- 2D・一様格子・定常層流でSDF境界と力を確定する。
- CPU FP64とCUDAで一致を確認し、同じケースをMetalへ移す。
- 随伴線形解法と配列寿命を固定する。
- SDFから境界、流れ、力までの微分を検証する。
- 取り付け部、禁止領域、最小寸法の共通検査を完成させる。

**成果物**：両GPUで動く共通ケース、勾配検証、ピークメモリ表。

**完了条件**：対象とする定常問題で、力・勾配・メモリが成立する。

### P3：制約付きSDF形状最適化 — 3か月目

**作業**

- 拡張ラグランジュ、形状勾配の平滑化、HJ更新を接続する。
- 候補の流れ再評価、採用・棄却、乗数更新、checkpoint/resumeを接続する。
- 再初期化、格子横断、幾何制約付近での挙動を確認する。
- 面積/体積等で問題を適切に制約した2D形状と単純翼で検証する。

**成果物**：再開可能な最適化実行、初期/最終形状、性能・制約の履歴。

**完了条件**：複数の初期形状で、実再評価による改善と制約充足を確認する。低Reでの成功は対象高Reの認定に代用しない。

### P4：3D形状最適化と対象空力 — 4〜6か月目

**作業**

- P1で選んだ一つの3D構成に進める。
- 有限翼、地面、多翼の順に対象物理を認定する。
- nominalと少数の地上高/yaw条件を逐次集約する。
- 独立したbody-fitted評価と格子収束を実施する。
- 一様格子で物理解像度と容量が両立しない場合だけ、静的2段階細分化を別の検証項目として追加する。

**成果物**：両OSの対応範囲表、3D改善候補、独立評価、総所要時間。

**完了条件**：適用範囲を明示した3D形状最適化が両OSで使用でき、最終候補の改善と制約が独立評価でも確認される。

6か月の第一目標はここまでとする。必要なRANS/境界/細分化の開発量が大きければ、対象を限定し期間を更新する。

### P5：任意トポロジー探索の実用化 — P4以降

**作業**

- 既存density/Brinkman経路の汎用応答勾配、連結性、非線形制約更新を完成させる。
- 複数の形状族で材料の追加・除去・接続・分離を検証する。
- density→SDFの受け渡し後に制約を再検査し、P3/P4の形状精緻化へ接続する。
- 最良密度解ではなく、抽出した実形状を最終評価する。

**成果物**：トポロジー探索→SDF精緻化→独立CFD評価の一連の実行。

**完了条件**：一つの翼に限定されず、複数形状族で制約付きトポロジー変更と実形状の改善が確認される。

SDFからの新規seed生成はこの段階の追加比較とし、seedと支持部を含む候補を評価する。成功しても既存density方式との比較を経て採用する。

## 10. 後続機能の導入条件

| 機能 | 導入する条件 |
|---|---|
| 静的格子細分化 | 必要な細部の解像度と容量が一様格子で両立しない |
| Goal-oriented AMR | 主問題・随伴・格子間転送が認定され、細分化の選択が支配的な課題になった |
| LKS/ALKS | 実測でpopulation保持が主制約となり、置換効果を比較できる |
| SDFの新規トポロジー生成 | density経路の探索能力との比較基準ができた |
| L-BFGS等 | 正しい勾配と再現可能な更新があり、反復回数が支配的になった |
| POD/ML初期値 | 直前解の再利用後も初期化に時間を要し、履歴データが蓄積した |
| 正式なmultifidelity trust-region | 定期監査でモデル差が把握でき、局所補正と半径更新を実装する価値がある |
| 非定常統計量の最適化 | 定常近似では対象の設計判断ができないと確認された |
