## 2. δ/3 ルール（B-5(a)）から導かれる下限
oracle の不確かさ U を δ の 1/3 以下に抑える割当（`U ≤ δ/3`、これは定理ではなく割当）を置くと `δ ≥ 3U`。
- U = 最大 SE（3.67%）→ δ ≥ 約 11%
- U = 3 項の線形和の最大（12.63%）→ δ ≥ 約 38%
- U = formal の最大相対誤差（7.57%）→ δ ≥ 約 23%
どの U を採るかで δ は 11〜38% の幅になる。係数 3 は割当であって定理ではなく、`tolerance_options.md` が戒めた「SE を δ/3 と同一視する」「SE と他の誤差を足して δ にする」に近い計算なので、**目安の幅であって根拠ではない**。
U = formal の最大相対誤差は、内部 ε での応答予測誤差であって勾配誤差ではない（代理指標）。

## 4. 私の推奨（根拠は §2 までの数値。数値そのものは判断事項）
D（2 段）を第一候補にする。3a で oracle の不確かさが支配する比較（案 C）、3b で AD 自身の整合を機械精度近傍で見る。案 C の `max` 形が欲しければ、GRAD-01 の変更を別タスクとして起こす。
3a の δ_rel は §2 の 11〜38% の幅（目安）の中から、データを見る前にユーザーが選ぶ（例示: 25%、arbitrary illustration）。
S3 の spike で forward AD が通らない場合は、案 A か B に縮め、reverse 側の判断を #24/#39 に回す。
