## 0. v1 からの訂正（対抗レビューで確認された、私の誤り）

1. **「g のずれが 10% なら D0 drag・D1 drag も通る」は回帰の形に依存する。** P2a の 7.07% / 7.76% は `q = g + c·ε²`（重みなし）の値。v1 が B-3 に書いた `S = g·ε + c·ε³`（重みなし）で同じ 3 区間を当てると、D0 drag は **12.3%**（D1 drag は 6.8%、D1 downforce は 6.6%）になる。重みなし S 形式は大 ε の点（15 mm）に引っ張られる。つまり、必須の D0 が重みの取り方ひとつで 10% の線をまたぐ。**回帰の重み付けは、dry-run の前にコードで固定しなければならない。**
2. **3 次の項（ε³）は、実際の曲率の形を取り違えている可能性が高い。** D0 drag の q − g は、1.5〜50 mm で ε にほぼ線形に増える（約 −6.6 / −7.4 / −7.1 per mm）。これは ε³ ではなく ε|ε|（奇数の 2 次、非解析的な応答）の形で、[0.5, 15] mm での残差 rms は ε|ε| が 3.9 µN、ε³ が 15.6 µN。ε³ の余分なパラメータが曲率を吸収するため、入れ子区間の安定性は誤った形をほとんど検出できない（シミュレーションで、真が ε|ε| で g の偏りが +10.9% のとき、10% の tolerance は 100% 通る）。
3. **σ_S（力のノイズ）の測定元が存在しない。** baseline の反復は bit 同一で床は 1e-8 N（実質ゼロ）。「2〜4 µN」は滑らかな当てはめからの残差で、再現ノイズではない。ε≦1.5 mm の残差 rms は全体で約 2.6 µN（downforce 3.4、drag 1.3）で一定でもない。
4. **D1 が「弱い」とは言えない。** 力の大きさは弱くない（|g|: D1 downforce 105、D2 downforce 95、D0 downforce 796。D1 drag 64、D0 drag 104、D2 drag 170）。D1 の問題は 4〜7% の波打ち。「XFID と P2a の両方で弱さが測定済み」という v1 の記述は、検証できる文書にない。
5. **「SDF の奇数部が D1/D2 は D0 の約 1e-10 倍」は事実だが、「混合符号で体積が打ち消す」は私の解釈**（P2a の note には D1/D0 の比だけがある）。
6. **P2a の g のずれの不確かさ（jackknife）は大きい。** 各区間 3〜4 点・2 パラメータでは、1 点を除くと残りは厳密に当てはまってしまい、SE は意味を持たない。意味のある値（D1 downforce [0.5,15] mm で 5.9%、D0 drag [0.5,15] mm で 10.8% など）でも、7〜8% のずれと同程度の大きさ。
7. **tolerance は「用途から導出」したとは言えない。** 10% は P2a の数値が分かった後に書いており、「oracle の不確かさ = 許容の 1/3」から出る値は 6.7〜10% で、10 か 7 か 5 かは決まらない。モデルの形、回帰の形、区間、holdout ε、σ の出所はすべて R5 の後に選んでいる。

## 3. B の決定案（ユーザーが決める項目。v1 で「決定済み」のように書いた箇所を判断項目に直す）

- **B-1**: R5 の FAIL は固定。旧 gate（共通 5 点・±5% plateau）の下での判定は覆さない。新 gate は「FD-08 契約 v2」として別に登録する。**要承認**
- **B-2**: 目的は「局所方向微分 g の推定と、その不確かさの定量」に置く。FD→secant の変更はしない。**要承認**
- **B-3（モデルと推定）**: **重み付き**最小二乗を主推定にする。重みは `1/√(σ0² + (ρ·S)²)` 形で、σ0 と ρ を**数値で、dry-run の前にコードに固定**する。主モデル `{ε, ε³}` に加えて、代替モデル `{ε, ε|ε|}` も当てはめて報告し、**2 つのモデルの g の差を評価項目に入れる**（誤った形を検出するため）。**要承認**
- **B-4（direction の扱い）**: D1 を特別扱いしない。**gate は direction ごとに適用し、PASS した direction だけを「FD-qualified」とする。** FD-08 全体の PASS は、事前に固定した被覆規則（案: 校正する方向のうち 3/4 以上が qualified）で決める。GRAD-03（#23）は qualified な direction だけを使う。**これは #23 の「every registered direction」という文言の変更（スコープ縮小）になるため、明示的な承認が必要。** 代替案: D1 を必須にしたまま進める（単純で誠実、ただし失敗確率が高い）。
- **B-5（tolerance）**: 数値の出所を次のどれかにする。**要決定**
  - (a) GRAD-03 の誤差基準 δ（勾配と FD の許容差）をユーザーがまず登録し、oracle の不確かさ ≤ δ/3 を導く。
  - (b) δ が決まらない場合、既定値（暫定案: g の相対 SE ≤ 10%、入れ子区間の g のずれ ≤ 15%、2 モデル間の g の差 ≤ 15%、holdout ≤ max(3σ̂, 15%)）を**感度表（5/10/15/20%）つきで dry-run の前に hash 固定**する。この値は私の暫定案で、GitHub に根拠はない。15% の根拠は、シミュレーションで D1 型の波打ちを持つ系列が 80〜99% 通り、誤通過は範囲内の真値でほぼ 0 だから、というだけ。
- **B-6（新しい direction）**: 滑らかな低次の法線変位ローブを 1 種、calibration の方向に加えるか。**判断**: 加えれば D0 型の滑らかな方向が 2 つになり、direction ごとの qualified の被覆が増えるが、新 hash・生成契約・float32 ゲートの実装が要る。加えなければ実装は軽いが、D0 以外に滑らかな方向がない。
- **B-7（formal の独立性）**: 現行の fresh33 は再現性の確認にすぎない。独立な検証の形を選ぶ。**判断**:
  - **(推奨) predict-then-run**: calibration で各 direction の (ĝ, ĉ) を固定し、**どの当てはめにも使っていない内部の ε**（例: 新しい 3 つの ε × ± × 4 方向 = 24 state）を新しく解いて、固定した予測と tolerance で比較する。新しい direction の契約が不要で、solver が決定論的でも新しい phi バイト列が入るので情報がある。
  - 取り置き direction（別 seed の filtered 方向、形の違うローブ）: 2 試行にすぎない（2/2 PASS でも合格率の 95% 下限は約 0.22）。「protocol が一般化するか」には答えるが、GRAD-03 が必要とする「各 direction の ĝ が信頼できるか」には答えない。併用するかは判断事項。
- **B-8**: R6 を最後の calibration とする。R6 も科学的 FAIL なら、微分 oracle 路線そのものを再協議（#47 STEP-01 と #48 LOWDIM-01 を主にする判断を含む）。**要承認**

## 4. 実行の二段階

### 段階 1（solver-free、codex 実装、停止点あり）

私が先に **FD-08 契約 v2 の仕様書**（モデル、重み、評価項目、パラメータの数値、決定木、停止則）を書いて対抗レビューにかける。承認後に codex が実装して停止する。

1. 評価器: 重み付き最小二乗（共分散つき）、主モデルと代替モデル、入れ子区間の g、holdout ε の予測、符号、絶対量。出力は direction ごとの 3 値（PASS / FAIL / UNRESOLVED）と数値。
2. **合成データでの誤通過率・誤棄却率のシミュレーション**: 滑らか、ノイズあり、D1 型の比例的な波打ち（4〜7%）、ε|ε| 型の曲率（真の g の偏りが 10〜25%）、弱い応答。**評価器が ε|ε| 型を検出できること**を受け入れ条件にする（v1 の評価器は 10% の偏りでも 100% 通った）。
3. **R5 への dry-run は行わない。** R5 の 0.5〜5 mm 帯は 3 点しかなく、holdout がなく自由度 1 で、証拠にならない（0.05/0.15/15/50 mm を使うと SNR≈1 か誤指定域）。代わりに、合成データのシミュレーションと、仕様書の hash 固定で代える。
4. σ̂ の測定元の設計: baseline 反復（情報なし）の代わりに、**ε を (1 ± 1e-3) だけずらしたジッター反復**を各方向に 2 state 入れ、再現しない変動を直接測る（案、段階 1 の設計表で検討）。
5. ladder・state 数・予算の設計表（§5）。新しい direction を選んだ場合の生成設計。

## 7. リスク

- 重み付き当てはめでも、D1 型の波打ち（4〜7%）があると、10% の入れ子 tolerance は五分五分になる（シミュレーション）。新しい方向が D1 型なら、joint の通過確率は低い。
- 滑らかな新方向でも、D0 drag のように曲率が強く、使える ε 帯が狭い可能性。
- tolerance の数値は私の暫定案で、GitHub に根拠がない（B-5）。
- 取り置き方向 formal は実装が大きい。predict-then-run の方が小さい。
- B-4 の #23 のスコープ縮小は、承認が必要。
