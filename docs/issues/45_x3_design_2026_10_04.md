# #45 X3 design: formal XFID with grid-phase ensembles (proposal, not registered)

Status: **design proposal; nothing is registered or run.** It fills the "fields required before immutable registration"
of `45_xfid_comparison_contract_draft.md` using the X1 inputs and the X2 measurements. All six qualification flags remain
false; any verdict will be scoped to uncertified geometry and the registered physical profile.

## 1. What X2 and FD-06 say about resolvability

OpenFOAM single-phase noise (X2, centered secant S, upper bound, per state pair): drag RMS 9.2e-5 N, downforce RMS 2.9e-4 N.
WaterLily responses to the same named directions at epsilon = 5 mm are known only from FD-06 (upstream body + normal floor,
v17, flow_24; **not Candidate C**, so a scale estimate for design only, never a verdict). With S = (R(+eps) - R(-eps))/2:

| contrast | WaterLily S [N] (FD-06) | SNR, 1 phase | SNR, 32-phase mean |
|---|---:|---:|---:|
| D0 drag | -6.9e-4 | 7.5 | 42 |
| D1 drag | -3.4e-4 | 3.7 | 21 |
| D2 drag | -8.6e-4 | 9.3 | 53 |
| D0 downforce | +3.7e-3 | 12.5 | 71 |
| D1 downforce | -5.0e-4 | 1.7 | 9.7 |
| D2 downforce | -4.9e-4 | 1.7 | 9.4 |

Reading: with one grid phase per state, D1/D2 downforce would be UNRESOLVED; averaging 32 phases (if noise averages as 1/sqrt(M),
to be tested by the calibration) resolves all six if OpenFOAM's physical response is of similar size. If OpenFOAM's response is much
smaller, that is itself the answer the experiment must be allowed to give (UNRESOLVED or DISAGREE), not something to design around.

## 2. Proposed design

- **States (7):** baseline and D0/D1/D2 at +/- 5 mm, the X1 STLs (hash-bound to `xfid45_stage_v_input_2026_10_04/result.json`).
- **OpenFOAM side (Kaggle CPU, ~77 s/case):** each state at the same M = 32 rigid sub-cell shifts, drawn from a registered
  low-discrepancy set inside [0.5, 4] mm per axis magnitude with all three components non-zero (so no ensemble member sits on the
  symmetric phase seen in X2) and with +/- mirror pairs per axis to cancel a linear translation effect. Common shifts across states.
  Formal run: 7 x 32 = 224 cases (~4.8 h), two kernels if wall time matters.
- **Calibration (disjoint, run first):** baseline-only null contrast: R(shift_a) - R(shift_b) over the same shift set gives the
  phase noise of a single state and tests the 1/sqrt(M) averaging; also check that the ensemble of S is not biased relative to one
  phase. 32 cases (~41 min). Calibration cases cannot satisfy formal evidence.
- **WaterLily-C side (Kaggle T4):** the frozen composite Candidate C identity, flow_24, v17, window [80,120], the 7 states, one run
  each (deterministic in FD-06: baseline repeat noise span 0). Roughly 110 s per run.
- **Response and rule:** forces in N; per direction centered secant S for drag and downforce in both solvers. OpenFOAM S is the
  phase-ensemble mean with its standard error; a contrast resolves only if |S| exceeds 3x the calibrated standard error and the
  absolute floor from the calibration (strict inequality; equality is UNRESOLVED). Signs compared only where both solvers resolve.
- **Required comparisons (registered a priori):** the six centered-S sign contrasts. Candidate ordering is reported for the downforce
  objective among the six perturbed states but is not a required comparison, because requiring every pair to clear a floor would
  make AGREE unreachable by construction (a decision for the user; the draft contract lists ordering as part of the verdict).
- **Verdict:** AGREE / DISAGREE / UNRESOLVED exactly as in the draft (only a resolved representative DISAGREE stops Track C).
- **Environment:** the host OS is recorded per case (`environment.json`); X2 showed Jammy and Noble give bit-identical v16 results.

## 3. Decisions I need (defaults proposed above)

1. epsilon stays at 5 mm (existing STLs) rather than 10 mm (needs new STL derivation; doubles the signal).
2. Ensemble size M = 32 and the 3x standard-error rule.
3. Required comparisons: the six S contrasts only, ordering reported but not required.

## 4. Sequence after approval

calibration kernel (32 cases) -> check averaging -> register formal criteria (floors, shifts, hashes, verifier) -> formal OpenFOAM
kernel(s) and WaterLily-C run -> verdict recorded in #45. The runner and registrar generalize the X2 ones (per-case STL and shift
vector).
