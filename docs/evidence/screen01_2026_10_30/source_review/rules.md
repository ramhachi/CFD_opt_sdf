## Findings

### R1 (P1) `main` cannot write any outcome on the no-finalist branch: it demands `freeze3.json`, which is never written without a finalist

- Location: `analyze_screen01.py:722-727` (`fz = {n: freeze(n) for n in ("freeze1", "freeze2", "freeze2_1", "freeze3")}`, then `finalist_json_sha256` from `freeze3`) with `freeze()` at 521-524; `screen01_freeze.py:152-154` (`freeze3` starts with `SC.req(bool(fin.get("finalist")), "no finalist: freeze 3 is not written (registration §5.4)")`); `tests/screen01/test_screen01_analyze.py:861-868` (`Disk.stage_finalist` writes `freeze3` unconditionally).
- Registration: §2 (row G2: freeze 3 follows `finalist`; row F: "pushed iff a finalist exists"; row A: one `main`), §5.4 (no finalist: F is not pushed; the outcome is NO_GAIN or INCOMPLETE), §5.8 steps 1-3, §10 (freeze 3 = finalist.json SHA, confirmation campaigns, budget), §9 ("refuses without the freeze records").
- Scenario: G2 ends with no feasible candidate (`NO_FEASIBLE_CANDIDATE`), or the best feasible candidate is below `g_min J - 3 SE` (`GAIN_BELOW_MIN_AT_SELECTION`, 3.2 % of OC replicates in the registered row), or G1 has no NC / both kernels lost (INCOMPLETE, steps 1 and 3). `finalist.json` has `finalist: null`; `screen01_freeze.py freeze3` refuses by design, so no `freeze3.json` exists; `analyze_screen01.py main` then raises "freeze3.json is missing: the analysis binds to the frozen records (§10)". Reproduced with the test pipeline after deleting the `freeze3.json` the fixture writes: `main_no_gain_no_feasible -> ValueError freeze3.json is missing`. Every registered outcome that ends before F (all of step 3, and steps 1-2 when there is no finalist) can therefore not be written once, and `finalist.json` of that branch is never bound by any freeze (§2: "its SHA-256 is recorded in the following freeze"). The only way out is to edit frozen code, i.e. an amendment after freeze 1.
- Fix: either (a) let `screen01_freeze.py freeze3` write a record for `finalist: null` (kind `screen01_freeze3`, `finalist_json_sha256`, `finalist: null`, no campaigns, no budget), and make `run_main` skip the campaign / table requirements of `f32` and `f48` when the finalist is null (it already does through `need`); or (b) in `run_main`, when `fj["comparable"]["finalist"] is None`, take only `freeze1/2/2_1`, accept `finalist.json` without a freeze 3 pin, and record its SHA-256 in `analysis.json` (the freeze script then needs a different place to bind it). Prefer (a) (one place, the freeze script, and the pin of §2 stays). Add a disk-pipeline test with a null finalist and no `freeze3.json` fixture shortcut.

### R2 (P1) `check_frozen` matches by basename: `states.json` is ambiguous in the real `freeze1.json`, so every stage refuses

- Location: `analyze_screen01.py:527-529` (`hits = [v for k, v in fz["file_sha256"].items() if Path(k).name == Path(path).name]; SC.req(len(hits) == 1 ...)`), called on every path through `load_roles` (559-560) and `frozen_sources` (641-647); `screen01_freeze.py:40` (`REUSED` contains `docs/evidence/unc01_2026_10_20/states.json`) and the freeze-1 path list that adds `docs/evidence/screen01_2026_10_30/states.json`.
- Registration: §10 ("refuses to run without these records and checks every campaign, table and written-once output against them"; freeze 1 lists `states.json` and the reused code).
- Scenario: `freeze1.json["file_sha256"]` will hold two keys with the basename `states.json`: the UNC-01 one (tracked) and the SCREEN one (untracked at HEAD, but `screen01_freeze.py` requires every bound path to be tracked, so it must be committed first). `check_frozen(fz1, EV/"states.json", "states.json")` finds two hits and raises "not the states.json frozen in freeze1" in `rs`, `finalist` and `main` before any table is read. Reproduced with the real `REUSED` list and the real file hashes: `REFUSED: .../screen01_2026_10_30/states.json: not the states.json frozen in freeze1`. The test fixtures hide it: the synthetic `freeze1` of `Disk` (tests:835-838) lists only the three sources, the SCREEN `states.json` and one fake profile.
- Fix: key on the repo-relative path: `rel = Path(path).resolve().relative_to(ROOT).as_posix(); SC.req(fz["file_sha256"].get(rel) == SC.sha256_path(path), ...)`. Same for campaigns (`docs/harness/<name>`), sources and `infra_signatures.json`. Test with `screen01_freeze.REUSED` in the fixture's freeze 1.

### R3 (P1) A kernel classified `NOT_INFRASTRUCTURE` cannot be declared lost, so the registered default branch of §9 blocks the analysis; per-state DATA_LOSS is unreachable with real tables

- Location: `analyze_screen01.py:790-798` (`parse_lost`: only the five ids of `infra_signatures.json` are accepted), 553-555 and 604-605 (a kernel needs a verified table, a `--lost` citation, or `--budget-stopped`), 767-787 (`classify_infra` returns `NOT_INFRASTRUCTURE` as the default); `docs/evidence/screen01_2026_10_30/infra_signatures.json` (`default_statement`: such a kernel "is NOT infrastructure: its runs are DATA_LOSS ..., never a reason to rerun"); tests:693, 699-700 (the registered DATA_LOSS causes classify as `NOT_INFRASTRUCTURE`) and 1210-1214 (an unknown id is refused).
- Registration: §9 (INFRA_LOSS table, "default = not infrastructure"; "a divergent run ... or a candidate the solver cannot handle is DATA_LOSS for that state-phase, never a reason to rerun"), §5.1 (DATA_LOSS: "per-state cap exceeded or did not finish"), §5.9, §5.11.17 (every `--lost` cites the signature it matched).
- Scenario A: one state of `g1k11` runs into the 900 s per-state cap, or Julia exits non-zero (`campaign_runner_template.py:280` raises, `ERROR.txt` is written, the remaining states never run). `infra` returns `NOT_INFRASTRUCTURE` (no rerun, per §9). The kernel has no verified table (`campaign_verify.check_kernel` requires DONE and no `ERROR.txt`), `--lost g1k11=<anything true>` is refused by `parse_lost`, and `stage_input` refuses with "have no verified table and are not declared lost". The study cannot write `rs.json`. The one accepted workaround is the undocumented abuse of `--budget-stopped` (R5), which records nothing.
- Scenario B (same root): a NaN force makes `SC.host_forces` fail (`finite(summary...)`), so the kernel fails `verify`, which §9 classifies as `VERIFY_FAILED` = INFRA_LOSS, so one identical rerun (a deterministic NaN reproduces) spends 4.6 h of the §4.3 budget and the kernel is then lost whole via `--lost K=VERIFY_FAILED`, against "never a reason to rerun". In both cases the registered unit of loss (state-phase) is in practice the kernel (up to 39 runs), because the runner stops at the first non-complete state and the harness verify is all-or-nothing. Consequence for the analyzer: the `ok = false` / `null` branches of `valid_runs` (131-151) are dead code with the real loader (`load_group` always sets `ok: True` and finite forces); the only state-phase DATA_LOSS that can occur is the 0.25 bound.
- Fix: (1) accept the table's `default` (`NOT_INFRASTRUCTURE`) as a citation: `ids = {e["id"] for e in signatures} | {t["default"]}`, with semantics "no rerun, runs are DATA_LOSS", and have `infra --out` write a record (output-dir listing hash, ERROR.txt hash, log hash, classification) that `--lost K=SIG` must reference and that goes into the output record; (2) registrant decision before freeze 1 (not an analyzer change): whether a verify failure whose only cause is a non-finite force is `VERIFY_FAILED` (rerun) or `NOT_INFRASTRUCTURE` (no rerun), and a recorded note that state-phase loss means kernel loss under harness v1.1; (3) test: a `NOT_INFRASTRUCTURE` kernel through the disk pipeline.

### R4 (P2) Tables, the freeze chain and the reused code are not bound at run time (§10)

- Location: `analyze_screen01.py:532-556` (`load_group` never reads `freeze_sha256`, `source_commit`, `harness_tool_sha256` of the table), 521-524 and 722 (`freeze()` loads JSON without chaining), 641-647 (`frozen_sources` checks only `analyze_screen01.py`, `screen01_check.py`, `screen01_pool.py`); `screen01_freeze.py:54-69` and 71-79 record `prerun_freeze_sha256`, the harness tool hashes and the reused-code hashes.
- Registration: §10 ("checks every campaign, table and written-once output against them"); freeze 1 lists the reused code, the harness tool hashes and the registration / adoption SHA.
- Scenario: a state-force table verified against another prerun freeze of the same campaign (e.g. after an amendment re-freeze, §9) or by modified harness tools loads and is analysed. `freeze1.json` edited after `freeze2.json` was written (so that `frozen_sources` accepts a modified analyzer) is not detected because the chain `freeze2.file_sha256[freeze1.json]` is never compared. The analyzer uses `analyze_unc01.py` (`A.stats`, `A.tq`, `A.run_files`, `A.clean`), `campaign_schema`, and `fid01_designs` (state names) at run time, none of them hash-checked against freeze 1; the registration and adoption SHA of freeze 1 are not compared with the files (`common_record` writes the registration path only, not its SHA).
- Fix: in `load_group`, require `t["freeze_sha256"] == fz["campaign"]["prerun_freeze_sha256"]` (the record of that campaign id in freeze 2 / 2.1 / 3) and `t["harness_tool_sha256"] == fz1["harness_tool_sha256"]`; in `frozen_sources`, also check `scripts/analyze_unc01.py`, `scripts/fid01/fid01_designs.py`, the registration and the adoption record, and walk the chain (each freeze N holds freeze N-1 with the SHA of the file on disk).

### R5 (P2) `--budget-stopped` is unrestricted and leaves no trace; step 4 does not test "F not completed (budget)" itself

- Location: `analyze_screen01.py:553-555` and 604-605 (`stopped` accepted for any kernel of any group), `common_record` 634-638 and the `meta` of `load_group` 556 (the declaration is not recorded), `f_shortfall_causes` 410-414, `main_part` 467.
- Registration: §4.3 (budget stops apply to the pushes after G1), §5.11.15, §5.8 step 4, §9 (`--lost` needs a frozen signature).
- Scenario (reproduced with the pipeline fixture): `rs` with a table for `g1k11` only and `--budget-stopped g1k12`, no `--lost`, no signature: `rs.json` is written, `lost_kernels` and `kernels_lost` are empty, `lost_signatures` is `{}`, and nothing in the record mentions the stop; every G1 state silently has P = 1. The same flag silences a `g2` kernel. Separately, step 4 reaches BUDGET only through `not ok3 or e48 is None or ncf is None`; a budget-stopped `f48k14` with `f32a`, `f32b`, `f48k13` present would continue to steps 5-8 with |Phi_48| = 1 and could give GAIN (reachable only if the registered push order f48 first, then f32 is violated).
- Fix: restrict `--budget-stopped` to `{f32a, f32b, f48k13, f48k14}`, write the declared list and the `budget` decision record's SHA into the output, and add a step-4 clause: any registered confirmation kernel that is neither lost nor has a run row gives INCOMPLETE (BUDGET) regardless of the other tests (`f_shortfall_causes` already computes it; call it before the `ok3` test).

### R8 (P3) `valid_runs` lists invalid runs that have no valid parent run; §5.11.1 says they are not listed

### R9 (P3) A crash instead of a refusal when `--g1` is omitted; table hashes keyed by file name

### R10 (P3) Re-derivation is exact and unpinned to the environment

- Location: `analyze_screen01.py:665-670` (`verify_upstream` compares JSON-serialised floats exactly), 237-238 (1e-12 replay tolerance); `freeze1.json` records python / numpy / scipy / scikit-image versions (`screen01_freeze.py:54-69`) that the analyzer does not compare.
- Registration: §9 ("the analyzer re-derives each ... and refuses on any mismatch"), §10 (versions recorded).
- Scenario: `rs` is written on one machine / BLAS, `finalist` or `main` is run on another; an ULP difference in `lstsq` / `quad9 @ beta` makes `rs.json` "not re-derive" (a blocking refusal, not a wrong result), and a scrambled-Sobol difference across scipy versions would change the proposal names.
- Fix: compare with the cross-check tolerance (1e-9) for floats and exactly for names / indices; refuse with a clear message if the running python / numpy / scipy differ from freeze 1.

### R12 (P3, observation) `finalist.json` does not surface the G1 chain controls

- Location: `analyze_screen01.py:277-310` (`finalist_part`); registration §5.4 / §5.8.

## Verdict

`GO_AFTER_FIXES`. P1 to fix before freeze 1: R1 (no-finalist `main` blocked by `freeze3.json`), R2 (`check_frozen` basename ambiguity makes every stage refuse), R3 (`--lost` cannot declare a `NOT_INFRASTRUCTURE` kernel; state-level DATA_LOSS is kernel-level in the harness, needs a registrant note).
