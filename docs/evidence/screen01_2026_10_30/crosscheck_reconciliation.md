## 1. Decisions and reasons

### 1.1 `propose` semantics (§5.2; the 7 `rs_*` failures and `main_duplicate_target_point`)
| # | Point | Decision | Reason |
| --- | --- | --- | --- |
| A1 | position of `u*_tau` in its list | **first** (the literal text: "u*_tau followed by a cloud ..., ordered by ŷ descending") | the text is not defective: `u*_tau` is the registered constrained optimum, gating it first is the point of the step; a cloud point with a higher off-grid ŷ follows. `propose` sorted `u*` into the cloud: defect, fixed. |
| A2 | a point shared by two targets (the same name in two lists, e.g. `u*_1 = u*_1.5` when the drag margin is slack) | **gated once**, owned by the target whose list queued it first in the round-robin (target order within a position); later lists skip it; each list also holds a name once; the stop rule counts admissible points per owning target and considers the targets with >= 1 queued point; proposals are per owning target | admissibility is a deterministic property of the geometry, gating the same bytes twice spends one of 36 slots for no information and can only produce the same state twice in the proposals (a state cannot run twice). Ownership-by-first-list keeps the staggered-target hedge (the deeper-margin target then proposes its own best admissible point) and is the only reading a hand can apply without a tie-break table. `propose` gated it twice (per-target `seen`): fixed. |

Proposing points the surface predicts to be no better than the parent spends G2 runs on nothing; the restriction removes candidates and never adds one, so no acceptance rule is weakened. `propose` dropped `u*` and kept a thin band of cloud points: fixed. |
| A4 | argmax ties on the grid | the first grid point in lexicographic (pitch, camber, reflex) order, each axis `linspace(lo, hi, 81)` | both implementations did this (numpy `argmax` on the C-ordered `meshgrid(indexing="ij")`); confirmed in the text. |
| A5 | cloud mapping | `u = clip(u* + 0.25 (2x - 1), lo, hi)`, `x = qmc.Sobol(d=3, scramble=True, seed=20261032 + i).random(256)`, `i` the 0-based target index | both did this; confirmed in the text. |

## 2. `propose` change and the operating characteristics
`scripts/screen01/screen01_pool.py propose` now: `u*_tau` first; a target with `ŷ*_tau <= 0` contributes nothing (`argmax[tau].no_predicted_gain = true`, `n_candidates = 0`); per-list name dedup and freeze-1 exclusion as before; one queue with cross-list name dedup and ownership by the first list; the stop rule over the targets with a queued point; proposals per owning target (ties → gated earlier), then the rest by ŷ (ties → gated earlier); `n_candidates` = points owned in the queue; rounds never exceed the cap. `selfcheck` additionally asserts: no name gated twice, `u*_tau` is the first point gated under its target, a surface with no predicted gain yields no gating and no proposals. The OC (`screen01_oc.py`) calls `propose`, so it was rerun (`--reps 2000 --out docs/evidence/screen01_2026_10_30/oc.json`, seed 20261031 unchanged); old → new numbers in §4.
