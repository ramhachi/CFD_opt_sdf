# SCREEN-01 plan review — governance / controls angle (sonnet, independent, read-only)

Reviewed snapshot: registration revision 0 at commit c0a17ea2 (`docs/screen01_registration_2026_10_30.md`, SHA-256 1ae10739ec64660e59457489c52fd10ec68584c95b8c79122e2a4f3702d8e86c). Verbatim report of the reviewer (2026-10-31).

## P1 (must fix before freeze)
1. **Contradictory data-loss rules (§5.2 l.98 vs §5.9 step 1 l.128).** §5.2: "A mode with both axial states lost at both phases ranks last (DATA_LOSS); fewer than 3 modes with data → INCOMPLETE". §5.9(1): "every axial state and NC with >= 1 common phase; else SCREEN01_INCOMPLETE". A mode with both axial states lost is "continue" in one and "INCOMPLETE" in the other. Fix: one rule as a decision table; a lost axial state reduces that mode's s_m (or ranks it last); INCOMPLETE only when fewer than 3 modes remain, the parent is missing, or NC is missing.
2. **Infrastructure data loss can produce NO_GAIN (§9 l.184, §5.5, §5.9(3), §7 l.169).** G2 lost gives RS_NOT_FIT, no proposals, "finalist ... from the evaluated states"; G3 lost gives no proposals; lost G1 or R states shrink C_opt. If the reduced set has no feasible member, or the finalist is below x* − 3SE, the outcome is NO_GAIN; §7: no extra round, M4 decides. This is the INCOMPLETE vs NO_GAIN conflation; K_opt < 22 also silently breaks the K-matching claim. Fix: any NO_GAIN at §5.9(3) with `search_complete=false` (a frozen-design kernel declared lost, a proposal slot unfilled for loss reasons, states lost) becomes INCOMPLETE with cause DATA_G1/G2/G3. "No proposals" for lack of eligible pool members (not loss) is a legitimate NO_GAIN-path input.
3. **No mechanical treatment of divergent, non-finite or cap-exceeded runs (§9 l.184, §5.1-5.5).** "A divergent run, an unexpected value or a candidate the solver cannot handle is a result, never a reason to rerun" — nothing says how such a value enters topmodes, the OLS, `Delta_bar_drag <= 0` or the finalist argmax; a diverged state with a huge |Delta| ranks first and can become the finalist; NaN comparisons are undefined. Fix: non-finite, solver-failed, per-state-cap-exceeded or physically implausible (frozen bound) state-phases are DATA_LOSS for that state-phase, excluded from every estimator, and count under finding 2. Freeze the bound.
4. **The manual control is not a meaningful comparator under D (§3.5 l.58, §5.7, memo D7).** C1 has FID drag +5.8e-3 N (resolved, SE 2.3e-4): it violates drag non-increase by construction. C1 is also the only heave-free positive-DF combination in FID (C4 is a loss), so "chosen" is vacuous. A feasible hand reference is constructible from visible data: camber −19.7 is +1.3004e-2 / +1.998e-3 (DF/drag), pitch −0.7 is −8.953e-3 / −6.383e-3; pitch ≈ −0.22° cancels the drag and predicts DF ≈ +1.02e-2 N (3.8 % of J_b,48) at drag 0. Fix: pre-declare a drag-neutral hand design by a stated recipe (P0 gate-checked; frozen fallback ladder); keep C1 only as an "infeasible downforce reference" with a renamed label (e.g. DOWNFORCE_REFERENCE); disclose that the reference is built from visible forces.
5. **The random control is not "the same space ... and budget" (§3.5 l.59, §5.7 l.120, memo D7).** R is 22 uniform 5-D points; the optimizer's 22 are 10 box-edge axial points (|u|=1), 9 D-optimal points and 3 proposals in a 3-D subset. R0 admissibility in 5-D (19 % pass) favours small |u|, so R members are near the parent; twist and sweep are visibly null levers and dilute R. OPT_BEATS_RANDOM is close to guaranteed by construction. "K_opt and K_rand are equal, so their selection bias is matched" is false whenever K_opt < 22 or K_rand < 22 (512 cap). n = 1 per arm. Fix (either): (a) draw R inside the selected 3-mode subset's frozen admissible pool (excluding design points) — needs a frozen per-subset draw, or R run at G2; or (b) keep the 5-D baseline but rename it RANDOM_BOX_BASELINE, register the |u|_inf distributions of both sets and an AMPLITUDE_MISMATCH label, make "matched" conditional on K_opt = K_rand, state it is a one-draw descriptive comparison.
6. **Post-force geometry/engineering steps can kill or change the finalist (§2 G3 row l.28, §5.6 l.116, §5.9(4), §9 l.185).** The STL chain check runs on the finalist after forces are visible; failure → FINALIST_INADMISSIBLE → NO_GAIN with no fallback. "Engineering defect found by a smoke before freeze 2/3: fixed and re-frozen" at freeze 3 happens after the finalist is known; a fix that touches finalist or R-best bytes is an unobservable re-selection. Fix: compute the chain check for every admissible pool member at P0 and make it part of admissibility; delete step 4; state that no amendment may alter the identity or bytes of finalist, R-best or M (such a defect gives INCOMPLETE); specify sealed-stage smokes as parent-only at a phase outside 0-16.
7. **The §14 inventory mislabels or omits deviations from #64 and the roadmap.** Phase rotation: #64 says "世代内は共通位相で比べ、世代ごとに位相を回す"; the draft uses k=11,12 for G1, G2 and G3 — not in §14. S_b/S_c: #64 requires stating which σ_d components map to S_b and S_c; the draft contains neither; say explicitly SCREEN does not use them. R3: #64 says a sign split is a fail; the draft's R3_UNRESOLVED → INCONCLUSIVE means an unresolved sign split is not a fail and a correct-sign result under 3 SE is not a pass; §14 says "equal / resolution-aware". "No extra floor": G adds the one-sided lower bound (+2.5e-4 N at P=4, 3.4 % of x*; +3.5e-4 at P=3) and moves P(GAIN | true = g_min) from ~0.49 to 0.013; §14 says "equal (resolution added)" — it is stricter; #64 and the handoff say "追加 floor にしない". Fix: label these rows stricter/looser/not-in-#64 honestly.

## P2 (should fix)
8. Sealed kernels have no NC and no parent replay (§4.2 l.78, §5.6 l.115/117); the decision estimator has no chain check. Fix: add NC (roll) at each sealed flow_32 phase and a parent replay at phase 11 (inside the 6.4 h slack); NC at sealed phases and a replay mismatch > floor → SCREEN01_INVALID; add a null candidate (parent bytes under a candidate name). The x-translation NC tolerance is about ±8e-4 N (3.5σ at P=2), ~11 % of x*.
9. D allows GAIN with an unresolved drag constraint; memo D9 "only resolved favourable rules give GAIN" is false; PASS_UNRESOLVED is the typical case at FID drag sigma_d 4.6e-4–9.4e-4 N. Fix: §1/§5.9 "GAIN = drag non-increase as a point-estimate sign; the resolved status is a label"; correct D9; require the label in the XV handoff; note the 1.36e-4 N drag floor is far below FID wide-mode sigma_d, so PASS_RESOLVED can be a 3-dof artefact.
10. The §1 question overstates R3 ("a gain of at least g_min that holds ... on flow_48"); the rule is sign/3SE. Fix: "has the same resolved sign on flow_48; g_min is judged on flow_32 only".
11. Visibility incompletely disclosed (§8): the sealed phases do not protect design choices made with FID forces visible (drag constraint form, point-sign decision, heave = 0, m_D, OC noise model, box/modes). Visible FID data are near-additive (camber −11.3 + scaled reflex: 13.218e-3 / 6.018e-3 vs measured C1 13.256e-3 / 5.831e-3); under additivity a drag-neutral camber−/pitch− mix gives ~+1.0e-2 N (3.8 % > g_min), so GAIN is a priori not unlikely and the OC null rows are not the visible-data expectation. Fix: add the additive prediction to §8; rescope "Nothing in §1-§7 was chosen after a force was seen"; note the topmodes rule has a predictable output.
12. The z-lattice rationale is overstated (§3.1, §4.1, memo D2): camber, reflex and pitch displace the surface in z by comparable amounts; the unphased z systematic is common to exploration and sealed phases, so a winner's curse in it survives the sealed re-estimate; OC "sealed bias ≈ 0" holds only for in-plane noise. Fix: state that all candidates carry an unphased z systematic, heave removes only its rigid component; add to the claim ceiling; consider a z-shift NC or an R3 magnitude label.
13. sigma_disc is mis-sourced (§5.8, §6): 1.4474e-3 N is the G3-set residual SD (essentially V3 one-shift placement noise), not a WL-to-OF discrepancy; XV requirements §2 and the preparation note warn against reusing it; 7e-4 retention-spread is the right-class quantity. Fix: label it a planning stand-in, report both, keep XV_MARGIN descriptive.
14. §7 pre-commits XV ("XV-01 is registered with the frozen finalist ... regardless of the XV_MARGIN label"); a SCREEN registration cannot bind a later registration or the compute decision; at g_min the label is almost always THIN. Fix: "XV-01 becomes eligible for registration".
15. INFRA_LOSS is not mechanical (§9): "for an infrastructure cause" is the operator's judgement; no class for a harness-verify failure. Fix: a frozen log-signature table (install, GPU identity, Kaggle error, session kill) with default = not infra; a verify failure is INFRA_LOSS (rerun once), then INCOMPLETE.
16. The amendment clause is unsatisfiable (§9): "before any verdict-relevant output is read" is meaningless after topmodes. Define verdict-relevant = sealed and flow_48 forces; require G2, G3 and sealed campaign files to be generated by a frozen builder and checked byte-equal.
17. No analyzer-defect protocol after a written-once output (§9, l.3): require synthetic-table tests of every decision branch in freeze 1; a second independent implementation of the decision tables (GEOM-03 checker precedent), cross-checked before each write; after a write the output stands and a discrepancy is reported beside it; the source review also covers the rev 1 delta.
18. P0 sequencing and the terminal pool rule: P0 precedes the source review (admissibility produced by unreviewed code); prescreen outputs are untracked; §3.3 ends at 256 points with no terminal rule. Fix: re-run or re-validate P0 with the reviewed code fingerprint and commit it; add a terminal rule (an inadmissible subset is NO_RS; if topmodes selects it, INCOMPLETE/POOL); any pool-rule revision applies uniformly to all 10 subsets pre-freeze.
19. Budget rule (§4.3): T counts only the f48 kernels, missing unfinished sealed f32 kernels (7,160 s); push order unspecified; slack 6.4 h; the cap turns Kaggle variance into INCOMPLETE. Fix: T = finished walls + estimates of all unfinished formal kernels, specify push order, or "exceeding the cap stops the pushes and goes to the user".
20. Re-registration caps and two-look inflation (§7): cap shared or separate is unclear; a re-registration after INCONCLUSIVE gives the same finalist a second look and inflates false GAIN. Fix: a total cap for #64; fresh seeds and phases ≥ 17; no pooling of sealed data; the second look's rule is not weaker; say what "M3b-2" means.
