# GEN-01 plan rev 0 (7bb2049e, SHA-256 7a1432c0...) review, angle N: numerical

(Opus reviewer, 2026-11-01, verbatim. Monte-Carlo and arithmetic scripts were kept in the reviewer's scratchpad, not in the repository.)

**Verdict: GO_AFTER_FIXES.** The architecture is sound: a discrete adjoint on morphed body-fitted meshes, filtered normal displacement as the design variable, and a toolchain bake-off before anything else. The problem is §3.4/§3.5. As written, the gradient contract and acceptance rule do not implement Carter's theorem, cannot separate good gradients from bad ones, and have inconsistent constants. ADJ-00 also cannot measure the memory and robustness that the plan itself names as binding.

## Findings

**N1 — P1 — §3.4: the contract is not Carter's condition, and it cannot test it.**
- What Carter actually requires (ICASE 89-45 preprint of the SIAM 1991 paper): weak condition (12) <e_k, g_k> <= xi_g ||g_k||^2, equivalent to "the directional derivative along g_k, divided by ||g_k||, is at least 1 - xi_g"; one-sided, gives only liminf ||g_k|| = 0 for the approximate gradient. Strong condition (13) ||e_k|| <= xi_g ||g_k||; only this gives grad f -> 0. Function-error conditions (7)-(9): |ared - cred| <= xi_f1 pred. Coupling (14): xi_g + xi_f1 < 1 - eta_2. With a scaled trust region, (19)-(20): the error must be measured in the trust-region metric.
- Item 2 matches neither condition. With an error orthogonal to grad f of relative size xi and an isotropic random direction, adj/FD - 1 = xi C with C standard Cauchy. P(one direction in [0.7, 1.3]) = (2/pi) arctan(0.3/xi): 0.50 at xi = 0.3, 0.34 at 0.5, 0.21 at 0.9. Both of two directions: 0.25, 0.12, 0.04 (Monte-Carlo, n = 400). The test rejects gradients Carter admits and passes bad ones 4-20 % of the time. Redrawing until the response is >= 5 sigma_J biases the sample towards g.
- Work F shows it: from the post-D3 plan §6.2 table (2 random directions) a ratio-of-sums estimate of the relative error is 0.13 for downforce and 0.24 for drag, well inside Carter's typical xi_g = 0.5, yet drag seed 2026 has adj/FD = 0.685 and fails item 2.
- Items 1, 2 (gradient direction) and 3 all measure the same thing: the error component along g. Item 3 (rho >= 0.25 on the first 3 steps) also fails a correct gradient whenever the initial radius is too large (Carter remark 4: unsuccessful steps are normal). Item 4 uses a cosine, which cannot see magnitude errors.
- The theory does not cover the chosen optimiser: MMA (NLopt CCSA) is not a trust-region method; Carter covers unconstrained trust-region. The constrained analogue is Heinkenschloss & Vicente 2002, inexact trust-region SQP (recalled).
- Fix: (a) test (12) with a central FD along g_k in the trust-region metric (Carter §4, two extra evaluations); (b) estimate (13) by ratio of sums over K Gaussian directions drawn in the filtered metric, xi_hat = sqrt[(sum (adj - FD)^2 - noise term) / sum FD^2], register an upper bound (simulation: 5-95 % band [0.33, 0.75] at xi = 0.5 for K = 16, [0.27, 0.92] for K = 8); (c) replace item 3 with "rho >= eta_1 is reached within <= 3 radius halvings"; (d) make item 4 a relative error, not a cosine; (e) use trust-region SQP, or MMA inside an explicit outer trust-region acceptance loop. Confidence high.

**N2 — P1 — §3.4 is tested only at the start; the condition must hold along the whole trajectory.** Any absolute error floor (partial convergence, frozen turbulence, wall-function and limiter kinks, base-mesh dependence, continuous-adjoint inconsistency) breaks a relative condition as ||g|| -> 0. ADJ-00 and "the first 3 steps" certify nothing near the optimum; a biased gradient converges to the adjoint's own stationary point. Carter §4: when (12) is used and the convergence test triggers, g must be recomputed at the highest attainable accuracy. Fix: run the (12) check at every accepted iterate (+2 primals per iteration, about +2,500 to 6,000 core-h for a WING-3D campaign); register the stopping rule ||g||_TR <= e_floor / xi_g, with e_floor from item 4. Confidence high.

**N3 — P1 — §3.5 constants contradict Carter's (14).** Acceptance at rho >= 0.25 means eta_1 = 0.25, so eta_2 > 0.25 and xi_g + xi_f1 < 0.75. With pred >= 3 sigma and |ared - cred| <= 2 sigma_d, xi_f1 ~ 0.67, leaving xi_g < 0.08: the rule admits almost no gradient error. Allowing xi_g = 0.5 needs xi_f1 < 0.25, i.e. pred >~ 8 sigma_d. Fix: derive (eta_1, eta_2, xi_g, k in pred >= k sigma_d) jointly and register all four; or a noise-aware ratio test such as Sun & Nocedal 2023 (recalled). Confidence high on the arithmetic; using a 2 sigma bound for a deterministic condition is a modelling choice to register.

**N4 — P1 — §3.5: sigma_J mixes three different noises, and 3-5 samples are too few.** Carter's (7) bounds the error of the computed difference; within a morph campaign from one base mesh the errors are common-mode, so what matters is the SD of the paired difference between consecutive morph states (sigma_d), not an absolute sigma_J. T2-0c: remeshing noise 0.2-0.9 % of Cl, morph noise 24x lower (h/c 0.224 only). If sigma_J is built from remeshing, 3 sigma_J is 0.6-2.7 % of Cl per step, so LOOP-2D-01's "every step gain >= 3 sigma_J" probably fails by construction; if sigma_J is the morph noise, the noise used for claims is understated. Sample size: for 3 / 5 / 16 / 32 samples the one-sided 95 % upper bound on sigma is 4.42x / 2.37x / 1.44x / 1.27x the sample SD (FID-01 used 32). Iteration-window variance needs an autocorrelation correction (batch means). Fix: register two floors: sigma_step = SD of paired morph differences plus the window standard error (acceptance); sigma_claim = remesh / sub-cell-shift ensemble with >= 16 samples plus base-mesh realisation (gains and claims, upper confidence bounds). Confidence high.

**N5 — P1 — §3.4/§4.2: nothing tests whether the gradient is stable across meshes.** A discrete adjoint is exact for J_h on one mesh, and the optimiser will exploit the mesh-specific part of J_h. Project record: T2-0c morph derivative depends on the base mesh by 26-29 % at h/c 0.134; FID-01 retention 0.57-0.77; slopes vary 50-100 % across grids and placements. §3.3 quotes only the favourable 24x. Fix: in ADJ-00 and every stage, compute the filtered gradient on >= 2 independent base meshes (separate snappy realisation or sub-cell shift); record their relative difference (ratio-of-sums) and the directional derivative of the first accepted step on the second mesh; descriptive in ADJ-00, thresholded from WING-3D on. Confidence high.

**N6 — P1 — §4.2: the ADJ-00 cases cannot answer the binding question.** §5.1 says memory and robustness bind, but no case measures them: case (1) is a 2D structured TMR mesh and case (3) a 2D section; neither says anything about memory per cell on snappy polyhedra with layers at scale. He 2020 attributes the Jacobian's density to the SIMPLE/Rhie-Chow 3-level stencil, larger on split-hex meshes. Case (2), Ahmed 25 deg, is the slant angle where steady RANS is least well-behaved (recalled); with item 4's 1e-8 residual a toolchain can fail for primal reasons, triggering "none pass -> fallback" on the wrong evidence. Fix: add case (4) running the production chain (snappy with layers, the production morph, node variables and the filter) on a 3D wing plus endplate (IFW geometry) at >= 3e6 cells; measure peak RSS for primal and adjoint in explicit and Jacobian-free modes; record where the primal stalls; in the selection rule record "primal not convergent" separately from "adjoint failed"; use a better-behaved slant angle (e.g. 35 deg) or report both. Confidence medium-high.

**N7 — P2 — §1.2: the Work F / P6 lesson is misreported.** The Work F mismatch was epsilon-stable (FD 4.37787 vs 4.37772 over eps 1e-4 to 1e-3); the post-D3 plan §6.1 says it is not a truncation or noise problem. "Source grid refinement brings all ratios near 1" (1.15 / 1.11 / 1.14) is P6, the porous DF2 line, not Work F. The real cause was continuous-adjoint / discrete-primal inconsistency: dxdbSurf and dSdb cancel with opposite signs and the result depends strongly on the convection scheme (linearUpwind moved Cd by -11.5 %). "Only take FD controls on directions with response >= 5x noise" fixes a cause that was not present. Fix: correct the row; discrete adjoint stays primary for the right reason; "includeMeshMovement false broke the control" is verified (1.04 -> 1.33). Confidence high.

**N8 — P2, blocking for WW-01 — §3.6/§11: "freeze the unsteady parts" does not freeze the linearisation.** Residuals and convergence certificates are global; wheel wakes are inherently unsteady (IFW-W std >= 5 % after 41 convective units); the adjoint carries information upstream (floor and diffuser downforce adjoint passes through the front-wheel wake); Krakos & Darmofal: even small output unsteadiness gives large adjoint errors. Under §3.5 every WW-01 and CAR-01 evaluation could be rejected. Fix: move this from §11 "decided" to "hypothesis"; register a WW-00 probe before WW-01 (steady convergence with a rotating wheel and wing, adjoint convergence, a Carter check); pre-define the fallback (windowed objective and adjoint, or a region treatment).

**N9 — P2 — gen_cost.py: the arithmetic reproduces, but the inputs are inconsistent with the plan.** WING-3D is modelled with 2 responses at 1 OP; §6.4 has downforce, drag and separation margin at 2 OPs: 17,500-69,000 core-h, $665-2,622 (2.6x). CAR-01 with 4 responses at 2-3 points: 236k-1.45M core-h, $9.0k-55k, against $30k. Billing: WING-3D runs on 60 of 192 cores; billed by node it is 115-425 node-hours, $825-3,060, not $261-969 (3.2x). Not costed: deep convergence, per-iterate checks (N2), sigma ensembles, FD tests, URANS checks. Fallback: 2K with K = 30-50 gives 75k-300k core-h ($2.9k-11.4k) per single-point campaign, above the $4,000 cap. Spot: AWS HPC instances may not be available as Spot (recalled); "spot-heavy, $20-30k" needs a verified instance type.

**N10 — P2 — §3.1/§4.1/§5.1: the memory and time anchors come from a superseded code path.** He 2020 (verified): 10,141,696 cells on a structured wing mesh; primal dropped 13 orders in 3,000 steps; adjoint tolerance 1e-6; partial derivatives by coloured FD with [dR/dw]^T and its preconditioner stored explicitly; memory 73.2 vs 1,146.2 GB; adjoint/flow 2.2-1.7 on 192-1,536 cores; Jacobian-free "future work" (for ADflow, Jacobian-free saved up to 30 % memory). DAFoam v5 is AD-based on the OpenFOAM-AD fork, so neither 113 kB/cell nor 1.7-2.2 has been measured for the code the plan would use. The DAFoam FAQ's sizing rule is 2 GB per 10,000 cells (200 kB/cell): CAR-01 ~4,660 GiB, 7 hpc7a nodes (plan says 4); WW-01 2 nodes; WING-3D 559 GiB, 1 node. Jacobian-free still keeps the preconditioner matrix; do not plan on more than 30-50 % saving. Fix: use 113-200 kB/cell in the cost model and take the time ratio from ADJ-00 case (4).

**N11 — P2 — §3.2: the filter is underspecified.** Helmholtz length ~ R_conv/(2 sqrt 3) (Lazarov & Sigmund 2011, secondary source), so "r_c = 30 mm" differs by ~3.5x depending on the filter meant; the BMW radii are VM convolution radii. VM's x = A s gives A A^T smoothing while a Sobolev gradient applies the filter once (sqrt 2 in Gaussian width). Mesh independence needs the mass-weighted inner product; the adjoint gives nodal, area-integrated dJ/dx; a Euclidean nodal gradient makes the step depend on local surface refinement (snappy levels jump by 2x). GEOM-K1's symmetry test is wrong: F = (M + r^2 K)^-1 M is self-adjoint in the M-inner product, not the Euclidean one; use the dot-product identity. Which nodes are the variables: snapped CFD boundary nodes (change at every remesh) or design-surface nodes (need a transfer operator T with a dot-product-tested T^T, as in Work F D1/D2)? The normal is undefined at trailing edges, endplate edges and feature edges; the radius lower bound should use the coarsest surface element in each patch.

**N12 — P2 — §3.2: "SDF h ~ r_c/4" mixes two length scales.** r_c is the design-update scale; h must resolve the parent geometry. For the wing r_c = 10-20 mm gives h = 2.5-5 mm, but trailing edges ~1 mm, slot gaps 5-15 mm, edge radii 3-5 mm. The surface -> phi -> surface round trip at each checkpoint will blunt trailing edges and close slots: a systematic jump in J, not noise. GEOM-K1 tests idempotency, not fidelity. Fix: choose h per component from the parent's minimum feature, register a round-trip gate on the parent (Hausdorff distance and |delta J| <= sigma_claim).

**N13 — P2 — §3.3/§4.2: the morph operator must be the same everywhere.** The discrete J_h depends on interior node positions, so dJ/dX_surface depends on the morph map. ADJ-00 FD perturbations, the production morph and the adjoint chain must use one operator; each toolchain has a different one (IDWarp in DAFoam, elasticity in SU2, Laplacian-type in ESI's E-SI). Also register: a per-step displacement bound relative to r_c and the layer stack (BMW 10 mm); a fail-closed post-morph checkMesh gate; claims as "remeshed final vs remeshed parent" inside the sigma_claim ensemble, not "morph gain minus checkpoint jump".

**N14 — P2 — §3.6: the regime constraints are not differentiable.** "Designs failing the convergence certificate count as constraint violations" is a barrier with no gradient; the trust region collapses at the boundary, where downforce maxima tend to sit. The reversed-flow area fraction integral H(-tau_w) has a delta derivative on the separation line and is noisy with wall functions; it will probably be active at the optimum, so its threshold decides the answer like r_c. Fix: smooth it (KS, smoothed Heaviside, or a Cp-recovery form), include this response in the ADJ-00 FD checks, register the threshold with a sensitivity report.

**N15 — P2 — §3.4: fail-closed details are missing.** The epsilon ladder in mm relative to r_c; a definition of "plateau"; NOT_EVALUABLE = fail; which "residual" (DAFoam's nonlinear residual or OpenFOAM's per-equation initial residuals; 1e-8 may be unreachable); pre-registered direction seeds and a redraw rule; the ratio convention (Work F used FD/analytic; the plan adjoint/FD); item 1's ">= 5 sigma_J" can be met by inflating epsilon.

**N16 — P2 — §4.1: toolchain facts.** SU2 v8.6.0 (verified): "Pressure Based Solver" (#2812) is under Experimental Features with no adjoint support stated; "Make CUDA acceleration compatible with discrete adjoint" (#2888) is about compatibility, not an adjoint solve on the GPU. snappy's polyhedra are not native SU2 elements (recalled), so the SU2 control runs on a different mesh. DAFoam FAQ: if the adjoint does not converge, switch div(phi,U) to upwind; Work F shows that changes Cd by -11.5 %, so it must be a registration event, not a tuning knob.

**N17 — P3 — theory wording.** A first-order shape Hessian is matched by an H^1/2 preconditioner; H1 regularises (content below r_c effectively frozen within ~30 iterations). "Mesh-independent convergence" holds only in the consistent metric. Hadamard's theorem is first-order and assumes a smooth boundary. The "0.5 or more" relative gradient error is already in the 1989/1991 theory abstract, not only in Carter 1993.

**N18 — P3 — minor.** The Mac estimate ignores the 172 GiB primal memory and Rosetta. The DAFoam FAQ suggests 1e4 cells/core, against the model's 5e4 floor. 30 iterations is optimistic (BMW stopped at its iteration limit). Before using the build difference (DAFoam's v2506-AD vs the ESI v2512 image) as "independence", check that both give the same J on the same mesh.

## What the plan gets right and must keep
- A discrete adjoint as primary with an independent control, and toolchains qualified on standard cases before any project case.
- Morphing within a campaign, remeshing only at checkpoints, recording the checkpoint jump.
- phi used for composition and as the constraint language, not as the design variable.
- r_c changes the answer, and is registered.
- Non-converged primals recorded as results and not retried.
- Claims only as paired differences plus retention on another mesh family and model.
- Mesh-movement terms mandatory.
- The low-dimensional FD fallback, which keeps the system generic.
- Money is not the binding constraint; memory and robustness are (survives these corrections apart from CAR-01).
