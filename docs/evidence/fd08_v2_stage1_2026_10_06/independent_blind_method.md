# Independent FD08v2 stage 1 checker provenance

The checker was implemented using only `spec.md` in this directory, which
contains the evaluator specification and synthetic-scenario specification.
No primary source, primary output, registered evaluation helpers, or R5 data
were inspected or imported. NumPy is the only third-party computational
dependency. The specified existing Python interpreter is used as a runtime
only, without reading its project source.

The code and this note are sealed before receipt or evaluation of the fixed
20 fixtures. The sealing SHA-256 and Git commit are reported separately to
the parent agent. Results will be generated by the sealed `checker.py`.

## Interpretation details

- Sign subsets explicitly use largest-epsilon drops 1 through 3, retaining
  at least three observations, independently of `nested_drop` (default 2).
- Stability subsets use drops 1 through `nested_drop`, retaining at least
  three observations. Both models are fitted and reported for every subset.
- The `n < 4` and insufficient-degrees-of-freedom clauses take precedence
  for the verdict, so such input is UNRESOLVED, even if diagnostic failures
  can be computed. The otherwise-applicable non-magnitude failure takes
  precedence over a magnitude failure.
- Zero slopes do not share a positive or negative sign; the sign check
  fails. A ratio with zero denominator is undefined and is reported as
  JSON null with an uncomputable item rather than NaN or Infinity.
- All covariance matrices are in fitting units (first coefficient N/mm,
  second coefficient N/mm^3 for A and N/mm^2 for B); both g and its SE are
  also reported in N/m via the single conversion helper.
- No residual chi-square scaling or iterative reweighting is used.
- Endpoints for holdout are positional minimum and maximum epsilon.
  Every internal observation is held out separately, with a newly computed
  pilot fit and covariance from that training subset.
- Outputs are recursively rounded to 12 significant decimal digits and
  serialized with sorted keys and `allow_nan=False`.

## CLI and input

`checker.py INPUT.json --output RESULT.json`

The preferred input is an object containing `cases`, a list of objects with
`id`, `epsilon_mm`, `response_n`, and optional `params`. A bare case list or
a single case object is accepted, and optional top-level `params` are
merged with each case's overrides. There are aliases for `fixtures` and
`inputs`, and the input vectors also accept `eps_mm`, `epsilons_mm`, `s_n`,
and `S_n`.

Output includes full A/B coefficients, g, SE, nominal covariance, pilot
predictions, weights, predictions and residuals; A/B fits for all specified
subsets; all holdout fits and per-point errors, sigma and tolerance; all six
items' numerical values and Boolean status; and the three-valued verdict.
