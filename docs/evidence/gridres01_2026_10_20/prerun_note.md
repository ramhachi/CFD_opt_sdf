# GRIDRES-01 prerun note (flow_40 kernel)

Date: 2026-10-20. Plan: `docs/gridres01_plan_2026_10_20.md` with Amendment 1 (G1-G6 override the text above them). Evidence class (target): bounded multi-grid actual-primal response measurement at one parent along one direction, Re 80, Kaggle T4.

**Question.** At the OPT-01 v1 parent along the frozen Stage B direction, flow_24 and flow_32 disagree on the downforce response (flow_24 negative curvature, no capability; flow_32 near-linear, +4.75e-4 N at 1.25 mm). Does flow_40 side with flow_32, with flow_24, or neither?

**States (G2).** parent, +0.3125, +0.625, +1.25 and -1.25 mm along the Stage A robust direction: byte-identical to `docs/evidence/opt01b_stage_b_2026_10_15/inventory.json` (every phi hash re-derived from the pinned parent and direction raw files by `build_gridres01_inputs.py`; the state names are the Stage B names). flow_24 and flow_32 values are the retained Stage B CSVs, hash-checked against the Stage B analysis, matched subset of the same five states (no rerun; the parent run on flow_40 is a plain fresh run, no cross-grid byte identity exists).

**Grid construction (G1).** `scripts/waterlily_gridres01_job.jl` builds the case with the frozen `V16W4Sensitivity.build_case("flow_40", 40, BASE_MAX_M, origin, 0.025)` and validates it locally (dims 250x120x90, spacing 0.02 m, solver length 40, nu = 40/80, Re 80, origin, box) instead of the frozen validator that only knows n in {16, 24, 32}. No file under `julia/CFDSDFWaterLily/src` is edited; solver settings, time window [80, 120] tU/L, sampling and the Candidate C operator are those of the flow_32 job.

**Caps (G2).** Per-state timeout 1800 s, aggregate solver cap 9000 s (5 x 1800), kernel timeout 21600 s. Kernel `ramhachi888/cfd-opt-sdf-gridres01-f40`. One submission, no automatic resubmission.

**Quantities and verdict (G3, G4; downforce).** Per grid the changes relative to the parent (time-weighted window means, as Stage B) are fitted without intercept to a*s + b*s^2 on the four matched steps (the parent is a zero row); also the forward-only fit and the max residual. G_max = max(0, sup over s in (0, 1.25] mm of a*s + b*s^2). `FLOW40_SIDES_WITH_FLOW32` iff G_max(flow_40) > 4e-5 N; `FLOW40_SIDES_WITH_FLOW24` iff G_max < 2e-5 N (both strict; the edges are AMBIGUOUS); `AMBIGUOUS` otherwise (then the flow_48 branch below); `INCOMPLETE` on an integrity failure or a downforce fit residual above 2e-5 N on any of flow_24, flow_32, flow_40. The residual gate is on downforce (the verdict quantity); drag residuals are reported only. Report-only: contraction ratios for a and b (CONTRACTING if both <= 0.6), THIRD_VALUE, acceptance emulation per tested step (gain > 3e-5 N and drag change <= 0), drag a and b per grid. Retained matched-subset fits (computed by the analyzer from the real CSVs): flow_24 a = 9.8e-5, b = -2.28e-4 (residual 4.8e-6 N, G_max 1.05e-5 N); flow_32 a = 4.73e-4, b = -7.68e-5 (residual 9.9e-6 N, G_max 4.71e-4 N). The plan's figures (9.9e-5 / -2.28e-4, 4.75e-4 / -7.6e-5, 1.1e-5 N) are from all six retained states per grid and agree within a few percent.

**Conditional flow_48 branch (G2).** Only if the flow_40 verdict is AMBIGUOUS: same five states, 300x144x108, spacing 0.016667 m, per-state timeout 3600 s, aggregate cap 18000 s, kernel timeout 43000 s, same rule applied to flow_48 and reported jointly. The code and the inventory already parameterize it (`gridres01_states.GRIDS`); nothing about flow_48 is frozen or run by this freeze. It needs its own identity check, freeze, review, and a joint-reading rule before any submission.

**Use of the outcome (G5).** The direction was selected as the max-min of the flow_24/flow_32 predictions: a selected line, not a random draw. No GRID-01 amendment can rest on this result alone. SIDES_WITH_FLOW32 justifies the next step of broadening (the four Stage A basis directions at +-1.25 mm on flow_40, about 2.4 h) before any amendment; SIDES_WITH_FLOW24 keeps the both-grid rule and points at flow_32; AMBIGUOUS leads to flow_48 as above.

**Disclosures (G6).** Non-blind: the flow_24/flow_32 values and the quadratic structure are known before the run. Lattice commensurability confound: the design lattice (0.025 m) equals the flow_32 spacing, flow_24 is coarser than the lattice, flow_40/48 finer; the sequence changes resolution and lattice alignment together, and any convergence is that of this interpolated-lattice body only. The 3e-5 N floor is nominal; the 1e-5 N guard band is the scale of the fit residuals, not a noise measurement. Not claimed: grid independence, physical or Stage V downforce, a gradient, optimizer behaviour, flag qualification.
