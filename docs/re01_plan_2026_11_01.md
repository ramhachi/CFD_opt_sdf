## 0. はじめに：この計画で分かること・分からないこと

- **RE-01 では、FSAE の Re（翼弦基準で約 5e5）で何が起きるかは分かりません。** 分かるのは次の 2 点です。
  - Re 80 の v18 の板で得た差が、Re をどこまで上げても残るか。翼弦基準の Re_c で約 3.8e3 までで、5e5 の約 1 % にあたります。
  - 後流が非定常になっても、差を測る統計がまだ使えるか。
- **v18 は、Re ≳ 1e3 では失速した剥離流になる見込みです**（迎角 20.4°、厚さ 9.4 %）。この見込みは、Stage 0 で parent を Re_L 8000 で計算して確かめます。
- **このリポジトリで目標の Re に届いているデータは、T2-0 の 2D 翼断面だけです。** Tyrrell 026（Re_c 4.6e5、h/c 0.224、付着領域）の pitch、camber、後縁 flap の応答で、記述的なものです。
- **FSAE の領域に近づく安い道は、別の親を使うことです。** 付着流の cambered な翼を親にし、低い Re と 4.6e5 とで同じモードの傾きを比べます。そのため、次の 2 つを RE-01 と並行させます（§5）。
  - 付着流の親の探索（ATT-00、探索的）
  - 2D で同じモードを比べる橋渡し（BRIDGE-2D-00、準備のみで、条件付きで実行）

## 1. 問いと位置づけ

- **今の到達点。** v18（Re_L = 80、Re_c = 122、reduced laminar）での主張だけです。
  - SCREEN-01 は `SCREEN01_GAIN` です。
  - FID-01 は `FID01_GO` です。広いモードの差は laminar OpenFOAM でも 0.57〜0.77 の割合で残ります。
  - XV-01（#65、PR #77）は登録中で、資金を出す前に述べた P(PASS) は約 0.17 です。主な不合格の型は drag の不増加の不成立（`DRAG_VIOLATION`）で、downforce の利得の不足ではありません。
- **主な問い（RE-01）。** FID-01 の tier A 8 設計は、最適化器が選んだものではなく、Re 80 での OpenFOAM の fidelity もあります。その WaterLily での同じ位相どうしの downforce の差を考えます。各 Re の段 k での差を Re 80 の差に原点を通して回帰した傾き b_k（retention の傾き）が、0.3 以上を保つかを問います。
- **副の問い。** SCREEN の finalist、手設計 M、SCREEN の random 最良（R-best）の符号を見ます。加えて、tier A の傾きからの finalist の残差を記述的に報告します。これは、選ばれた設計が選ばれていない集合と同じように振る舞うかを見るためです。
- **主張の上限**（登録の最初の行に書きます）：
  - 主張できるのは、WaterLily（implicit LES、収束していない格子）での、登録済み v18 設計の差の Re 依存性です。Re_c は 3.8e3 までです。R1 では laminar OpenFOAM による符号と整合の確認が付きます。
  - 主張しないもの：物理的な downforce、格子独立性、評価器の GO、FSAE、Re ≥ 1e4、新しい Re で最適化器が選ぶ形状、提案器の転写。
  - Re 80 は creeping flow ではありません（Re_c 122 で、粘性の支配が強い定常流です）。
  - 前縁の境界層は、R1 の flow_32 で既に 1 セル未満です。そのため、どの読みにも「この solver 系統とこの格子列では」を付けます。
- **仮説**（結果ではなく、事前に置く予想です。判定には使いません）：
  - H1：tier A の傾きは、R1 で 0.3 以上を保つ。
  - H2：最初の非定常の段では、傾きが弱まる。
  - H3：Re_L 2500 では、弱まるか判定不能になる。
  - H4：CRN の比 σ_d/(√2 σ_F) は、Re 80 の 0.1〜0.3 から 1 に近づく。
- **regime の表は拘束しません。** 予想される流れの区分（Fable 調査 §2.2）は、判定に使いません。

## 3. RE-01 の設計

### 3.1 Re の段の候補と選び方

| 候補 | Re_L（Re_c） | 扱い |
| --- | --- | --- |
| R1 | 250（381） | **無条件で正式。** Stage 0 で viability を満たさなければ、登録をやめる（段を落とすのではない） |
| 450 | 450（686） | 800 が viability を満たさないときだけ、その代わりになる |
| 800 | 800（1,219） | 非定常の段の第 1 候補 |
| 2500 | 2,500（3,810） | 最も低い優先度。既定は記述的な probe |

非定常の段で正式にするのは、最大 2 段です。正式にするかは、Stage 0 のあとに charter の viability 規則（§4.2）で機械的に決めます。

Re を変えるのは、WaterLily の `solver_viscosity`（= n/Re_L）と OpenFOAM の ν だけです。そのため、Re をパラメータに持つ case 契約と job を新しい source として作ります。この source は、flow origin の z-shift（ATT-00 用）も持ちます。

新しい source は、Re 80 で SCREEN の生出力を byte 単位で再現しなければなりません。具体的には f32a の parent を phase 13 の flow_32 で再計算します（約 0.12 GPU h）。再現できなければ、何も実行しません。

### 3.2 設計（状態）と格子

- **flow_32**：各正式段で 4 phase（17〜20）、15 状態に加え、R1 では parent の repeat を走らせます（1 phase あたり 15 または 16 run）。

  | 区分 | 状態 |
  | --- | --- |
  | 基準 | parent |
  | 主（tier A 8） | `v18__pitch_m0.7`、`v18__pitch_p0.7`、`v18__camber_m11.3`、`v18__camber_m19.7`、`v18__camber_p19.7`、`v18__reflex_m29.3`、`v18__camber_m11.3_reflex_m11.3`（C1）、`v18__pitch_m1.3_reflex_p29.3_sweep_p11.3`（C4） |
  | 副 | finalist `v18__camber_m29.55_pitch_p0.155_reflex_p16.115`、M `v18__camber_m19.7_pitch_m0.38`（`camber_m19.7` とほぼ同じなので、順位の計算では重複に注意）、R-best `v18__camber_m28.656_pitch_m0.68_reflex_p2.727` |
  | 正の対照 | `v18__pitch_p3.1`、`v18__pitch_m3.1`（Re 80 で ±15 %、UNC-01 と SCREEN の G1 で一致） |

  | 決定性 | parent repeat（R1 と Stage 0） |

- **flow_48**：2 phase で、parent、C4（−12.1 %）、reflex −29.3（+5.9 %）を計算し、b_48/b_32 で格子の整合を見ます。finalist は載せません（2 phase では分解できないため）。
- **flow_64**：正式な段には使いません（裁定できる精度がありません）。
- phi の bytes はすべて登録済みで、新しい形状は作りません。heave は Re と無関係の z-lattice の artefact で落ちた（FID-01）ので、含めません。
- flow_48 と flow_64 は流れを細かくするだけです。形状は 0.025 m の設計格子からの補間です。

### 3.3 Re 80 の基準値

基準には登録済みの値を使います。tier A は FID-01 の flow_32 の phase 7〜10、正の対照は UNC-01 と SCREEN の G1、finalist、M、R-best は SCREEN の確認段階の値です。各値はファイルの名前付きの field から SHA-256 付きで読みます。

同じ phase での Re 80 の anchor は置きません。基準値の noise は段の noise の 8 % 以下だからです（N14）。

### 3.4 統計

- **主の推定量。** 段 k の flow_32 の差 Δ_k（4 phase の平均）を、Re 80 の差 Δ_80 に原点を通して回帰し、傾き b_k を求めます。対象は tier A の 8 設計で、90 % の t 区間（自由度 7）を付けます。FID-01 の G3-set と同じ作りです。
  - 残差には、noise と設計ごとの retention のばらつきの両方が入ります。
  - parent の共通誤差は、Δ_80 の符号付きの和がほぼ 0 なので、ほとんど打ち消し合います。
- **regime の条件付け**（regime は Stage 0 で、charter の規則により決めます）：
  - 定常の段：推定量 A（phase 間の SD）だけを使います。窓は Re 80 と同じ 40 CU（burn-in を含めて 120 CU。drift 規則に掛かれば 240 CU）です。
  - 非定常の段：窓は charter の式で決めた固定の W_k です。推定量 B（run の中の batch means による SE）は記述として報告し、片側で使います（A と B の大きいほうの SE で判定）。B のせいで段が判定不能になることはありません。CRN の比は記述量にします。
- **副の符号。** 非定常の段では、設計をまたいで pooled した σ_d で判定します。検出力は低いことを明記します。たとえば retention 0.5、SE_T 1.5 % のとき、finalist の符号が分解される確率は約 0.4 です。
- **順位。** Kendall τ は記述としてだけ報告します。

### 3.5 判定（段ごと、順序どおりに最初に当てはまるもの）

1. `INVALID`：parent repeat が bit 一致しない。
2. `NUMERICAL`：正式な run のどれかが発散するか、非有限値が出る。結果として扱い、再実行しません。
3. `INCOMPLETE`：
   - 原因を問わず同一の再実行を 1 回したあと、4 phase そろった tier A の設計が 6 未満になる。
   - または、予算で止まった（原因は `BUDGET`）。
4. `NO_RE_EFFECT`：parent の C_L と C_D が、前の段（R1 の場合は Re 80）との差で、どちらも 3 倍の合成 SE 以内に収まる。
5. `CONTROL_UNRESOLVED`：正の対照 pitch ±3.1 の符号が分解できない。推定量の失敗として扱い、物理の読みはしません。
6. `RESOLUTION_LIMITED`：b_48/b_32 の 90 % 区間が [0.5, 2] と重ならない。
7. `DOMAIN_SENSITIVE`（非定常の正式な段のみ）：流出側を +1 m 延ばした領域で、C4 の差が 3 倍の pooled SE を超えて変わる。
8. `NUM_SENSITIVE`（最も高い正式な段）：Poisson を itmx 64 にすると、C4 の差が 3 倍の SE を超えて変わる。
9. b_k の 90 % 区間 [LB, UB] による区分です。この 5 つで漏れも重なりもありません。

   | ラベル | 条件 | 読み |
   | --- | --- | --- |
   | `PERSISTS` | LB ≥ 0.3 | 保持率 0.3 以上で残る |
   | `WEAKENED` | 0 < LB < 0.3 ≤ UB | 正だが、0.3 以上かは分からない |
   | `LOST` | 0 ≤ UB < 0.3 | 0.3 未満に落ちた |
   | `REVERSED` | UB < 0 | 符号が反転した |
   | `INDETERMINATE` | LB ≤ 0 かつ UB ≥ 0.3 | 区間が広すぎる |

- **R1-OF（OpenFOAM の脚）。** tier A の V1/V2 の差を、Re 250 と FID の Re 80 とで、同じ shift（FID の 49〜64）で比べます。ラベルは 9 と同じ区分です。
  - これは符号と整合の確認です。V1 は一次の風上差分で Re の応答が鈍るので、V2 を、数値粘性の小さいほうの水準として読みます。
  - XV-01 の分析（1 回だけ書くもの）ができる前には、R1-OF の力を読みません。2026-12-06 までに XV-01 の分析ができなければ、`R1_OF_NOT_RUN` とし、R1 は WaterLily だけで読みます。
- **毎回報告する記述量**
  - 設計ごとの Δ_k/Δ_80（区間付き）
  - parent の C_L、C_D、Strouhal 数、rms と S(0)
  - CRN の比
  - finalist の残差
  - drag の差の傾き
  - Poisson の残差の分位
  - run ごとの費用
- **全体のまとめ。** 正式な段ごとのラベルを並べ、R1 から途切れずに PERSISTS が続く最も高い段を報告します。単一の総合ラベルは作りません。
- **独立 checker と OC。** 分析器（`analyze_re01.py`）とは別に、独立の checker を作ります。ラベル表は合成表で試験します。OC（Fable §1 の表を起点にしたもの）を、凍結 1 の前に登録します。

### 3.7 手順の規則

- **段の順序。** R1 → 最初の非定常の段 → 2 番目の非定常の段。
  - 非定常の段は、R1 の判定（`rung1.json`、1 回だけ書く）が書かれてから始めます。
  - R1 の後の凍結は、機械的に作る campaign ファイルだけを束ね、パラメータを変えません。
- **R1 で終わる場合。** R1 の主ラベルが `LOST` か `REVERSED` なら、非定常の段は規則により `NOT_RUN` です。裁量の余地は置きません。
- **kernel loss。** 発散は `NUMERICAL` とし、再実行しません。それ以外の loss は、原因を問わず同一の再実行を 1 回だけ行います（SCREEN と同じ）。
- **予算。** push の前ごとに予算記録を書きます（SCREEN §4.3 と同じ）。上限に掛かった段は `INCOMPLETE(BUDGET)` とし、規則は変えません。
- **kernel の上限。** SCREEN の 1.5 倍規則に従います。
- **変更の禁止。** 力を 1 つ読んだあとは、設計・格子・窓・閾値を変えません。第 2 の ladder もしません。

## 4. Stage 0：parent だけの探索的 probe と charter

### 4.1 charter（最初の run の前に commit し、hash で固定する）

- **run の表**
  - parent だけを、phase 1〜3（Re 80 でしか使っていない phase）で計算します。
  - 候補の各段（250、450、800、2500）で flow_32 を 3 phase、800 CU（R1 は 240 CU）走らせます。
  - 800 と 2500 では、flow_48 を 1 本、400 CU 走らせます。
  - Re_L 8000 で、flow_32 を 1 本、400 CU 走らせます。失速しているかを見る記述的な probe です。
  - 新しい source の byte 回帰（Re 80）も行います。
  - OpenFOAM の parent は、V1 と V2 を Re 250 で 1 case ずつ計算します。結果は status と反復数だけを読み、力は封じます。加えて、V2 の `linearUpwind` で status probe を 1 本走らせます。
- **読み出し**
  - 記録します：parent の力の時系列、drift、batch means、S(0)、τ_int、Strouhal 数、burn-in、1 CU あたりの step 数と max flux、GPU メモリ、wall、Poisson の残差の分位。
  - 設計の差は含みません。parent の C_L と C_D は記述として保存しますが、閾値には使いません。
- **固定するもの（Stage 0 から導かない値）**
  - 0.3 の帯、SE の目標 1.5 %、窓の上限 400 CU、各上限、run の表、regime 規則の定数、ラベル表
- **変更の規則**
  - 段を落とすことだけができます（発散、メモリ、wall、予算の記録による）。段の追加や移動はできません。
- **索引**
  - `docs/exploratory_index.md` の行は、run の前に書きます。失敗も含めます。

### 4.2 viability 規則（charter に書く）

1. burn-in B_k：後続の block の平均の SE の範囲に、block 平均が入る最初の 100 CU の block とします。ただし 80 CU 以上です。
2. regime：次の 2 条件を 3 phase すべてで満たせば定常、それ以外は非定常とします（周期的な流れは非定常に含めます）。
   - UNC-01 の half-window drift 規則を満たす。
   - 最後の 40 CU の batch means の SE が、parent の力の 0.1 % 未満。
3. S0_k：lift の零周波数スペクトル密度です。block の長さ 5、10、20、40、80 CU の batch means から求め、90 % の上限を取ります。3 phase の parent の時間平均の SD がこれと合わない場合は、大きいほうを採ります（片側、保守的）。
4. 窓 W_k：√(S0_k/W_k) ≤ parent の力の 1.5 % を満たす、100 CU の倍数のうち最小のものです。定常の段では 40 とします。
5. 費用 C_k：run の表と、実測した 1 CU あたりの step 数から計算します。
6. manipulation の前提：parent の C_L か C_D が、前の段との差で 3 倍の合成 SE を超えていること。満たさない段は `NO_RE_EFFECT` として落とします。
7. 数値：発散、非有限値、Poisson の上限に掛かる step の割合 1 % 超が、どれもないこと。

候補は次の 3 つをすべて満たすとき**正式**になります。

- W_k ≤ 400 CU
- C_k がその段の上限以下
- 優先順に積み上げた正式の費用の累計が 65 GPU h 以下

項目 6 と 7 も満たしている必要があります。選ばれなかった候補は、残りの予算が足りれば記述的な probe（parent、finalist、C4 を 2 phase、480 CU、flow_32、約 1.9 GPU h）を走らせ、足りなければ `NOT_RUN` とします。

**PROC-01 の読み方。** `docs/phase_plan.md` の PROC-01 には、探索的な結果は「a threshold, a gate」に使わない、とあります。この計画では、窓と段の選択を判定の閾値ではなく工学的なパラメータとして扱います。それらは、事前に書いた式で Stage 0 の parent の統計から機械的に決めます。判定の閾値はすべて Stage 0 の前に固定します。この読み方は、phase_plan の決定として記録します。

### 5.2 BRIDGE-2D-00：2D で同じモードを比べる橋渡し（探索的、上限 15 GPU h）
