## 0. はじめに：この計画が約束すること・しないこと

**前提。** 評価器は WaterLily（GPU、一様直交格子、BDIM、implicit LES、約 130 B/cell）。形は SDF で、流れの格子にそのまま乗せます。メッシュは作りません。OpenFOAM は **primal だけ**を検証器に使い、adjoint は使いません。DAFoam は使いません。クラウドの CPU は使いません。GPU は、ユーザーの手持ちの RTX 4070 Ti（Windows 機。WSL2 ＋ CUDA で Linux の harness を動かす）を既定にし、Kaggle の T4×2 を並列の小さい仕事に、レンタル（1 時間 0.35〜1.19 USD）は急ぐときにだけ使います。購入は要りません（§5）。

**約束すること。** **宣言した部品プリミティブの集合（翼素の板、端板の板、サイドポッドの箱）の上で、要素の数を先に決めずに最適化する**システムの構成と、その成立を段階ごとに事前登録した基準で確かめる道筋です。各段に合格・不合格・撤退の規則を前もって書き、最も安く決定的な試験（低 Re の要素数の選好が高 Re で残るか）を最初に置きます。

**正直に言っておくこと。**

- **「随伴法でトポロジーフリー」の随伴の部分は、当面ありません。** WaterLily の AD は tangent が指数成長して止まっています（#23）。ただし追加調査で、WaterLily の issue #358 に **QUICK の `10c−9u` の bound を外すか、cds／vanLeer にすると ForwardDiff と有限差分が一致する**という報告が見つかりました。本リポジトリは QuickTie（導関数の tie 平均）しか試しておらず、この λ の交換は未試験です。これを最初の安い実験（GRAD-00、Kaggle で 10 GPU 時間以下）にします。成功しても、非定常（カオス的）な後流の時間平均の勾配は別問題（shadowing が要る）で、勾配が主線に乗るのは定常な領域に限られます。
- **トポロジー自由度は「プリミティブ集合の上の要素数の自由」です。** 任意の形ではありません。この自由度に SDF と固定格子が要るのではなく、固定格子が買うのは「メッシュ不要」と「GPU の安い評価」です。これはユーザーの前提の一部を狭めるので、決定事項（§10 (b)）です。
- **WaterLily の物理の検証範囲は狭い。** 公開の検証は TGV（Re 1600）、球（Re 3700、直径あたり 88〜168 セル）、振動円柱（Re 7620）で、翼の Re 1e4〜1e5 の検証はありません。本リポジトリは Re 250 までしか回していません。本計画の格子（翼弦 60 セル、前縁半径 1.5 セル）では前縁剥離は BDIM の核に支配されます。FSAE の Re_c 2e5〜5e5 には壁モデルがないので届きません。FSAE の主張は WaterLily からは出ず、**転写の判定**（TOPO-2D-00、TR-01）からだけ出ます。それも「本リポジトリで未検証の RANS の内部での保持」であって、物理の downforce ではありません（§6.5 の表）。
- **Re_c 3e3 では要素数の物理が FSAE のものではない可能性が高い。** 後縁の境界層の厚さ（約 5c/√Re ≈ 0.09c ≈ 27 mm）が最小のスロット間隙より厚く、スロットの効果（Smith 1975）は境界層が間隙より薄いときに出ます。したがって低 Re の最適化は 1〜2 要素に落ちる可能性が高く、それは FSAE にとって最も情報の少ない答えです。**これを計算機を買う前に 2D で確かめます**（TOPO-2D-00、§6.2）。
- **薄い要素の下限は 3h ではありません。** 古典 BDIM は Lauber ら（2022）で (4+√N)Δx、WaterLily 1.8.0 の ε=1 では約 3.7h（3D）が必要で、BDIM-σ を実装すれば約 2.7h です。h = 5 mm なら要素は約 19 mm（BDIM-σ で 14 mm）以上で、FSAE の薄いフラップ（8〜10 mm）は表せません。下限は登録した梯子試験で決めます（§3.2）。
- **力の読み出しに系統誤差があります。** WaterLily の圧力の面積分は一様圧力で閉じず（issue #369）、表面がセルを切る位置に依存する 0.1〜0.5 % 級の誤差を出します。利得の判定尺度と同じ大きさなので、修正（control-volume の力、または提案中の `nds` 修正）を MW-01 の前の工学 gate にします（FORCE-00）。
- **非定常な後流では解像できる差が親の力の 2〜4 % です。** 共通位相の対差分の効きが落ち（RE-01 の調査 §4）、有限差分の勾配には 1 点あたり r = ⌈8σ_F²/Δ²⌉ の反復が要ります（σ_F 1.5 %、Δ 2 % で r = 5）。評価回数は「1 点 1 評価」の 5〜18 倍になります。定常な領域の親（ATT-00 の狙い）か、低い Re（1e3）での選別が前提です。
- **車両全体を薄い要素の解像度で一度に解くことはできません**（1e9 セル級）。「車両全体」は部品ごとの局所領域の最適化の列になり、床・ディフューザ・ノーズ・サスペンションのフェアリングは落ちます（表は §10 (c)）。これもユーザーの決定です。

## 1. なぜこの線か

## 3. 設計上の決定と、その根拠

### 3.1 表現と事象

- 多要素翼は要素ごとの解析 SDF の min。各要素はパラメタごとに解析的に再計算し、再初期化は要りません。可動要素は面で解析的に評価します（三線形格子を通すと、3h の板の中央で深さが位相により −1.5h から −h に落ちる：W-N1）。
- **距離の契約（2026-11-06、Codex WP6 の反例を受けて確定）。** 可動プリミティブの φ は解析的な implicit field で、無変形の stadium 板では厳密な SDF（|∇φ| = 1）、キャンバー／reflex 付きでは零等位面は v18 の式のまま距離は一次近似（|∇φ| = √(1 + f′²)）とします。WaterLily の `AutoBody.measure` は d を |∇φ| で正規化するので一次誤差は solver 側で補正され、本リポジトリの gate 2（band 内の median ||∇φ| − 1| ≤ 0.10）と同じ許容で扱います。登録する検査は、band 内の gate 2 と、数値の最近点距離との差 ≤ 2 % × t（開発時の既定。登録で確定）。union の min は重なりの内側で真の最短距離ではありませんが、重なりは scene gate で禁止するので band には現れません。rev 2 の Vertex Morphing の名残である r_c は、この線では使いません（ProblemSpec v3 は部品ごとのパラメタの範囲と刻みを宣言します）。
- **距離の契約の実装形（2026-11-06 b、WP6 フェーズ A の Opus review を受けて）。** 生の一次近似（|∇φ| = √(1 + f′²) のまま）は band 内の最近点距離との差が 3.9〜4.3 % t（|∇φ| で正規化しても 1.6〜3.9 % t）で 2 % t の許容を満たさないので、実装は **v18 の零等位面（多項式面）への固定 multistart 射影**（2 面 × 6 始点 × 13 Newton 反復）で距離を取る。独立検査で band 内の誤差 ≤ 1.1e-4 t、2h〜10h で ≤ 1.7e-8 t、符号は v18 と完全一致。Julia 側（GPU、Float32、AD）への移植は同じ射影を実装する必要があり、その費用と精度は未測定（MW-01 の前に測る）。**merge の例外**：`MergedElement` の min union は重なりの内側で距離ではなく（20° 交差で band 内の最大誤差 0.41 t）、scene gate が重なりを許す唯一の場所なので、merge 後の要素は「band 内の距離契約の例外」として gate の記録に明示し、BDIM の帯での影響は MW-01 の前に実測する。**種まきの向き**：downforce 翼ではフラップは主翼素の後縁の下流かつ **上**に置く（Zhang & Zerihan の配置）ので、種まきの候補位置は符号付きの offset（上下両方）を取り、policy が許す象限を宣言する。
- **scene gate**（要素単体の検査では見えない union の欠陥を見る）：厚さ ≥ t_min、間隙 ≥ g_min、R3 型の開口欠陥を solid と void の両方に、連結性、閉じた空洞、要素と端板の接合。拒否は CFD の前に無料で行い、予算に数えません（Westra ら 2026 と同じ）。
- **事象はすべて離散**です。種まき：ライブラリの薄い板を候補位置に置く提案。knock-out：要素を 1 つ外す提案。合体：重なりを許して 1 体にする提案。消滅は「厚さの下限に 2 チェックポイント留まった要素は knock-out 候補」。各提案は、チェックポイントで共有する親の位相集合（16 位相）に対する候補の 16 位相で、群逐次の対検定（片側、Holm で多重性を補正）で判定します。knock-out は **TOST（非劣性）の余裕を登録して判定**し、「差が見えないから削る」はしません（W-S3、W-N8）。
- **要素数の推定量**：最終形（事象あり）対「親の要素数に固定した同じ最適化器・同じ評価回数の腕」。これが「要素数の自由が効いたか」の登録した問いです。
- 事象の費用：チェックポイント 1 回あたり約 176 評価（親 16 ＋ knock-out 5 × 16 ＋ 種 5 × 16）。チェックポイントは 3 回（約 530 評価）。

### 3.2 解像度・間隙・配置（登録した梯子で決める）

- **厚さの下限 t_min。** Lauber ら（2022）の梯子を GEOM-S1／RES-00 で行う：物理の t を固定し h = 5／3.3／2.5 mm（t/h = 3／4.5／6）、8 位相以上（z を含む）、C_L・C_D と 1 つのキャンバー（または迎角）step の差を測り、最細格子に対する差の保持率が [0.8, 1.25] に入り、位相の SD が目標以下になる t/h を t_min にする。式は登録に書き、既定は t_min = 4h（BDIM-σ を実装すれば 3h を再試験）。
- **間隙の下限 g_min。** 2D の BDIM スロット試験（g/h ∈ {2, 2.5, 3, 4, 6}）で流束の誤差と位相の広がりを測り、同じ形の規則で決める。既定は 4h。
- **配置位相は 3 軸。** RE-01 の W1 で z の shift を加えた source を使う。地面は scene と一緒に動く BDIM の半空間（V = U）で、領域の壁にはしない（壁だと sub-cell の z 位相で h/c が最大 0.017 変わる：W-N4）。
- **剛体並進の事前検査。** 要素の x／z の位置を MW-01 で自由にする前に、同じ Re で剛体 x／z 並進の差が h 3.3 mm と位相で保持されるかを登録済みで確かめる（FID-01 の heave の教訓）。
- **領域。** 上面のブロッケージが要素数で変わるので、RE-01 と同じ DOMAIN_SENSITIVE の対照（領域を広げた親と候補）を置く。

### 3.3 Re と物理

- 選別は Re_c ≈ 1e3、順位は Re_c ≈ 3e3（h 5 mm）。確認は **同じ Re** で h 3.3 mm（Re と格子を同時に変えない）。Re_c 1e4 の run は記述のみ。
- FSAE の Re には届きません。転写は TOPO-2D-00（2D、最初に）と TR-01（3D、後で）で測ります。

### 3.4 統計

- **σ_d**：共通位相の対差分の SD（推定量 A）。非定常では推定量 B（batch means の run ごとの SE）と比べ、A と √(B_c² + B_b²) の大きい方を使う（RE-01 の契約）。16 標本以上、上側信頼限界。MW-01 の中の最初の凍結フェーズで、後で再利用しない状態について測る。探索的な run の σ は、前もって固定した式で予算と実現可能性の見積もりにだけ使う（PROC-01 の RE-01 の読み）。
- **主張**：最終形と親の 16 対 16 の片側検定（α = 0.05、σ_d の上限、新しい位相）。応答曲面の最適点や DFO の最終点は、必ず新しい位相で再評価し、SCREEN-01 の b_K（選択バイアス）を補正する。期待 P(PASS) を登録前に書く。
- **drag の制約**は片側の余裕付き。
- **事象**：§3.1。16 対で 2 % の効果に検出力 0.92、1 % に 0.31（σ_d 2.1 %、上限係数 1.44）。
- **FD を使う場合の反復**：r = ⌈8σ_F²/Δ²⌉。σ_F 1.5 %、Δ 2 % で r = 5。評価回数は式で登録する。

### 3.5 最適化器（登録時に OC で決める。R5 の範囲に注意）

- **主候補：逐次の応答曲面**（SCREEN 型）。要素パラメタの基底 8〜15 モード、45〜136 係数、2 次。全点でノイズを平均するので、1 点 1 評価でよい。R5（「スクリーニングと小さい応答曲面」）の範囲内。
- **代替**：Py-BOBYQA／DFO-LS（再始動でノイズに対処）、UH-CMA-ES（不確かさ処理付き。λ は既定の 4+⌊3 ln n⌋ 以上）。これらは R5 の改定が要る（§10 (d)）。素の CMA-ES（λ 12、60 世代）は不適切でした（学習の地平は n²/μ_eff ≈ 230〜290 世代、step-size 適応は強いノイズで失敗、世代最良の判定は 2.4 % 水増しされる：W-N7）。
- **有限差分の trust region**は、RES-00 が定常領域（σ ≈ 0.2 %）を示したときだけ。定数 (η₁, η₂, k) は反復した step 差分の上で再導出し、実現可能性（期待利得 /(kσ) ≥ 3）を登録前に確かめる。σ_d 2 % では k = 8 が 17 %／step になり成立しない（W-N6）。
- 最適化器の切替は、登録した固定一覧の中でだけ。

## 4. 登録済み適応キャンペーンの規約（本文で定義）

- **凍結する集合**：コードの SHA、WaterLily の版と GPU 機種（backend 識別）、プリミティブ集合、親、ProblemSpec、位相集合、σ の式、最適化器とそのハイパーパラメタ、事象の規則と余裕、チェックポイントの回数、GPU 時間の上限。
- **終了**：(i) 応答曲面の予測利得が trust radius で k σ_d 未満（NOISE_LIMITED。正常な終了）、(ii) DFO の ρ_end 到達、(iii) 評価回数の上限、(iv) GPU 時間の上限。
- **成果物**：最後に受理した設計を新しい位相で再評価し、b_K を補正して主張の検定に掛ける。
- **ラベル（網羅、優先順）**：INVALID_DEFECT（欠陥。原因記録付きの再開は 2 回まで）→ INFRA_LOSS（Kaggle セッションの喪失、GPU 障害。同一入力からの再実行のみ）→ INCOMPLETE_BUDGET（GPU 時間・評価回数）→ INCONCLUSIVE（主張の片側区間が 0 をまたぐ）→ FAIL（最終形が親より悪い、または drag 制約違反）→ PASS。事象の採否（TOPO_EVENTS_ACCEPTED／REJECTED）と要素数の推定量の結果はラベルと別に記録する。
- **再登録**：1 回。変えてよいのは原因ラベルから決まる固定一覧（ノイズ → 窓と位相数、解像度 → h、事象 → 余裕）だけ。最適化器の切替は一覧にあるものだけ。
- **評価の原子性**：同一入力からしか再実行しない。部分データは混ぜない。GPU 機種を変えたら backend 再適格化 gate（byte 参照は機種を跨がない）。

### 6.1 GEOM-S1

- 内容：プリミティブ集合（板、端板、箱）の解析 SDF と AutoBody 化、scene の union、固定部品の mesh-SDF、scene gate（§3.1）、3 軸の配置位相（RE-01 W1 の z-shift）、2D モード、ProblemSpec v3、harness v1.2（N の外側ループ、事象の記録）、保留する第 2 形状（後翼）のハッシュ固定。
- 合格：#32 の Birth-0（意図したプリミティブを正確に 1 つ作る）と Birth-1（要素数の変化を分類する）、解析 SDF の距離性質、scene gate の網羅と偽陽性率（sub-cell 位相で R0 型の alias が出ない）、2D と 3D の同一コード経路。

### 6.2 TOPO-2D-00（最初の決定的な試験。計算機の購入の前）

- Zhang & Zerihan（2003）の 2 要素の地面効果翼を基に、1／2／3 要素の 2D 系列を作る（要素は t_min 以上に厚くする。同じ系列を TR-01b の鋭い後縁版にも使う）。
- WaterLily 2D（Re_c 1e3 と 3e3、h = c/120、1 評価 0.1〜0.2 T4 時間）と、TR-00 で適格化した 2D RANS（Re_c 4.6e5、Kaggle CPU の T2-0 パイプライン）で、Δ(1→2)、Δ(2→3) の downforce と drag を、位相集合（WaterLily）と格子族の実現（RANS）の区間付きで比べる。
- **一致規則を先に書く**：符号の一致と順位の一致。不一致なら、要素数の自由は FSAE に転写しない可能性が高いことを記録し、MW-01 を「低 Re の方法論」としてだけ登録する（ユーザーの決定 (i) の材料）。
- ついでに MW-01 の最適化器の OC 用のデータ（2D の dry run）と、事象の規則の予行を行う。

### 6.3 MW-01：前翼（地面効果、要素数は自由）

- 親：Zhang & Zerihan の 1 要素を t_min に合わせて厚くしたもの（チームの CAD はスパン・厚さの制約で近似が要る。§10 (h)）。運転点：h/c 0.2〜0.3 の 2 点。Re_c 3e3、h は RES-00 で決める。
- 変数：要素 N_max = 5 × 6〜7 パラメタ。N の外側ループ ＋ 3 チェックポイントの事象。制約：規則の包絡、地面との clearance、g_min、t_min、drag ≤ 親（片側の余裕）。
- 最適化器：§3.5 の OC で（主候補は逐次の応答曲面）。
- 腕：固定要素数（要素数の推定量）、盲検の手設計（ハッシュ登録）、ランダム。
- 合格：主張の検定、要素数の推定量の片側区間 > 0（効かなければ「要素数の自由は効かなかった」を記録）、h 3.3 mm で保持率の区間が [0.5, 2]、OPT_BEATS_MANUAL／RANDOM。記述：同 Re の OpenFOAM 非定常層流 2 ケース。

### 6.4 RES-00（登録。MW-01 の前）

RE-01 の Stage 0 の式を流用しつつ、**登録 study として**：3D の 1 要素の親で、RESOLUTION_LIMITED（h 5 対 3.3 の比 [0.5, 2]）、DOMAIN_SENSITIVE、NUM_SENSITIVE の対照を親・1 つの要素 shift・1 つの要素追加に掛け、厚さと間隙の梯子（§3.2）と剛体 x／z 並進の保持を測り、σ_d と費用の実測で MW-01 の h と予算の式を埋める。

### 6.5 TR-00／TR-01／TR-01b：転写（FSAE の Re）

- **TR-00**：2D RANS パイプライン（T2-0、Kaggle CPU）を Zhang & Zerihan の 1 要素対 2 要素の ΔC_L で適格化する。T2-0b/c/d の NO-GO は絶対 Cl の評価器としてのもので、ここでの契約は **差の符号と比**。
- **TR-01**：MW-01 の複数設計（最終形、固定要素数の腕、手設計、ランダム最良、採択された事象の前後）を Re_c 4.6e5 の RANS（2 モデル × 2 格子族 × 8 実現）で評価し、**RE-01 型の保持率の傾き**（複数設計の回帰、Fieller の区間、分母は新しい位相の低 Re 値）を、モデル×格子族の**最悪値**で判定する。モデル間で符号が食い違えば INDETERMINATE。収束しなければ NUMERICAL（鈍い 19 mm の後縁は Re 2e5 で強く剥離するので、これが最も起こりやすいラベルです）。URANS の退路を費用付きで置く。
- **TR-01b**：同じ配置を実際の鋭い後縁の断面で描き直した版。別ラベル。

## 10. 決めたこと・登録で決めること・ユーザーに決めてもらうこと・確認できていないこと

- **決めたこと**：WaterLily（GPU）を評価器に、プリミティブの SDF の union を表現に、要素数の自由を外側ループと離散事象で、勾配なし（応答曲面が主候補）で開始、AD は GRAD-00 から bounded に、OpenFOAM は primal の検証器、クラウド CPU なし、DAFoam なし、TOPO-2D-00 を最初の決定的な試験に、購入は RES-00 の後。
- **登録で決めること**：t_min と g_min（梯子）、h、最適化器（OC）、σ の式、窓、位相集合、事象の余裕、N_max、各段の GPU 時間の上限、TR-01 のモデルと格子族。
- **ユーザーに決めてもらうこと**：
  - (a) 計算基盤：ユーザーの提案（2026-11-01）は手持ちの RTX 4070 Ti（Windows 機）。**これで足ります**（メモリ 12 GB ≫ 最大 7.7 GB、速さは T4 の約 1.6 倍、MW-01 約 17 日、計画全体 78〜102 日の 24 時間稼働、費用は電気代だけ）。確認事項：WSL2 ＋ CUDA で Linux の harness を動かせること（LOCAL-GPU-01）、24 時間稼働の可否、SUPER（16 GB）かどうか。Kaggle T4×2 は並列の小仕事に、レンタルは急ぐときだけ。購入は不要。
  - (b) **前提の受け入れ**：トポロジー自由度は「宣言したプリミティブ集合の上の要素数の自由」であり、随伴は当面主線に無い（GRAD-00 が成功しても定常領域のみ）。
  - (c) **範囲の縮小の受け入れ**：落ちる部品の表 — 床・ディフューザ（車両規模の領域を細かい h で解けない）、ノーズ・車体（粗い文脈のみ）、サスペンションのフェアリング（凍結）、端板（板プリミティブで扱うが MW-01 では固定）。残るのは前翼（MW-01）、後翼（RW-01）、サイドポッド（能力試験）。
  - (d) phase_plan の改定：R5（DFO／UH-CMA-ES の代替を許すか）、#23（GRAD-00 を DIAG ではなく事前分岐の試験として許すか）。
  - (e) rev 3.1 を **M4 の決定**として、XV-01 のラベルと独立に記録してよいか（MW-01 を XV-01 の前に登録するために必要）。
  - (f) RE-01 の改定：ATT-00 を先に、BRIDGE-2D-00 を TOPO-2D-00 に統合。
  - (g) 支出の記録：レンタルを始めるときの phase_plan／STATE の文。
  - (h) MW-01 の親（Zhang & Zerihan 系列を厚くしたもの／チームの前翼の近似）、規則セット（JSAE 学生フォーミュラ 2026 ＝ FSAE 2026 か）、チームの関与（CAD、盲検の手設計のハッシュ）。
  - (i) **「低 Re の方法論」だけが残る結果でも、この支出と人手を正当化するか**（TOPO-2D-00 が不一致のときに判断）。読者は方法論の論文（SMO、Computers & Fluids）か低 Re／MAV の分野で、車には何も与えません。
